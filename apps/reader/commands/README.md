# Shared typed product commands

`EXReaderCommands::reader_commands` is an independently installed C API over
`EXReaderRevisions` 0.3.0 and the existing product SQLite provider. It produces
new schema-v1 revision bytes in native code and calls `local_project` once.
Hosts pass typed fields; Java, Swift and desktop UI code do not build wire JSON.
Existing stored or received bytes never pass through this producer.

The three calls cover books, groups (shelf/tag/series), and memberships. Supply
the complete head set the UI actually observed; this producer sorts the new
parents and preserves the native transaction's expected-head check. A stale
snapshot returns `READER_COMMAND_REVISION` with `READER_REV_UNSAFE`. Conflicts
require an explicit command observing every current head. Delete/restore need
observed history, and a restore must satisfy the existing tombstone rules.

An empty group ID creates an OS-random global ID; an empty revision ID creates
an OS-random revision ID. Both assigned IDs are returned even if a later
transaction fails. For a create that must survive process death before a
response arrives, call the existing native `reader_revision_new_id` twice,
persist those IDs with the typed request, and supply both to the command.
An autogenerated identity cannot be recovered from a response that never
arrives. Retry with both known IDs and the same typed fields and observed
heads. Same ID/exact generated
bytes is a no-op, including after outbox acknowledgement. Reusing an ID with a
different command is a collision. Generated IDs are never chosen by a clock.

Membership first verifies retained book identity. A catalog-only or missing
book returns `READER_COMMAND_NEEDS_BOOK_BOOTSTRAP` before any writes. The host
must verify the exact retained original through the public SDK (format, SHA-256
and original bytes), then submit a book command using the **current product
title, author, favorite and host-derived NFC sort title**. Do not replace an
edited product title with fresh SDK metadata. Attach the local SDK mapping
after the product command succeeds. Keep a committed SDK original if product
work or local mapping later fails; these databases do not share a transaction.
The producer accepts no SDK-local identifier and never puts one on the wire.

All calls use the creating native product owner thread. A Java/Swift database
transaction cannot extend the metadata/history/outbox native transaction.
Android must move its catalog queries and mapping attachment to that same
native product owner before UI integration; acceptance here covers installed
Windows and Linux consumers only.

`reader_command_utf16` accepts counted native UTF-16 units and returns strict
standard UTF-8, including supplementary characters. It rejects embedded NUL,
unpaired surrogates and output overflow before publishing any bytes. Use it at
JNI/Windows text boundaries instead of modified UTF-8. It does not normalize
text. Existing 256-scalar/1024-byte group and 4096-scalar/16384-byte book text
limits are enforced by the revision and projection module.

Configure and install this directory after installing the revision/product
packages, then use `find_package(EXReaderCommands 0.1.0 EXACT CONFIG REQUIRED)`.
The Actions workflow `reader-commands.yml` builds that installation and separate
C/C++ consumers, verifies the actual SQLite source and sole link provider, and
exercises typed transactions, retries, faults, process kills, concurrency,
dependencies and Unicode. It also reruns the source/protocol/sync/projection
suites on the same source. Local work is source and Git only.
