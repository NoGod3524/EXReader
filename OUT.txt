② 跨平台不一致的具体来源

- ZipInfo.create_system 默认由宿主决定：Windows 为 0，Linux/macOS 为 3。两个生成器均显式固定为 0，保持已有固定时间戳、权限及排序后的成员顺序。
- DEFLATE 压缩器实现：Windows Python 的 zlib-ng 与 Linux zlib 对相同输入可输出不同压缩字节，影响 ZIP 成员及 Codex 内嵌 PNG IDAT。仅固定 ZIP 元数据后，首轮 Linux 验证仍失败。
- 最终 ZIP 使用 ZIP_STORED；PNG 使用显式编码的 stored DEFLATE 块，生成过程不调用压缩器。Codex PNG 改用 4-bit 调色板以保持相同 RGB 像素并满足原大小断言。
- XML namespace 属性来自显式有序 tuple；文件使用 write_bytes，不经文本换行转换。严格字节相等断言保留。
- 原有验收记录确认 XML/relationships 内容不变，33 个内嵌 PNG 解码后 RGB 像素相同；最大 Codex 文件 60444 < 61440 字节，Argon 14835 < 60000 字节。
