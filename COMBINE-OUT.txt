## 规格 1–7 的实现

- **解析**:支持 `text-combine-upright: none | all | digits [2-4]`,旧写法 `horizontal` 按 `all` 处理。
- **1 合成范围**:在同一文本节点内合成。`digits N` 取连续 2..N 个 ASCII 数字(默认 N=2)。`all` 取整个节点 1–4 个字符。
- **2 宽度**:合成块按横排宽度求和,缩放到不超过 1em,水平居中,整块只占一个 1em 的 advance。
- **3 基线**:按字形真实上下沿,把墨迹中心放到字身中点。
- **4 不可拆分**:块内后续字符并进首字符的字素和行段,所以任何断行或拆分都落不进块里。放不下时整块换行。
- **5 两端对齐**:块内不拉伸;合成字形不参与字间距分配和标点压缩。
- **6 不合成**:横排、`none`(含默认)、超过 N 位、`digits` 遇非数字、`all` 超过 4 字符或含空白,都不合成。
- **7 回退**:合成块一律按横排整形和度量,再缩放居中,不依赖字体的竖排字形。
- **新增公共标志** `EXR_GLYPH_COMBINED`:glyph matrix 和渲染层不用改。
- **开关**:没有加布局配置字段,避免改 ABI。默认值是 CSS 初始值 `none`,书内或用户 CSS 声明了才合成。草枕写了 `-epub-text-combine: horizontal`,所以会合成。用户 CSS 写 `text-combine-upright:none` 可以关掉。任务里“默认不合成”和“默认开启”有冲突,我按这个理解处理。

## 七项验收

1. **草枕真书**:共 25 个合成块,在全书第 2、459、462、463 页。两位数块 8 个:`12`(封面)、`22`、`62`、`12`、`46`、`47`、`17`、`28`。块的 advance 等于字号,偏差 0.00px:14.93、16.80、13.44px。像素实测墨迹宽 13、16、13px,小于字号,因为数字自带侧距。
2. **缩放与居中**:缩放比 0.9333(封面 `12`、`22`)和 0.96(463 页)。垂直偏移 −11.45 到 −14.25px。像素实测墨迹中心偏离字身中心,沿列向平均 0.98px、最大 1.21px,横向 0.17–0.62px。
3. **`2026`**:用合成数据,Reader.otf 28px、`digits 4`。缩放 0.4375,数字间距 7px,四位墨迹整体宽 26px,在 28px 字身内,清晰可读。
4. **行末只剩 0.5em**:`1`、`2` 都落在下一列的列首,整块 28px,没有拆开。第一列的余量摊到字间,块没有被拉伸。
5. **19 本回归**:18 本的页数、字形数、逐页像素哈希全部不变,其中含三本横排中文书。草枕只有上面那 4 页的像素变化。
6. **草枕页数**:464 → 464,没有变化。这本书只有封面和后付用了合字,25 个块不改变任何一页的行装填。全部 19 本合计 11,296 → 11,296。
7. **ctest**:191/191 通过。新增 3 组:`native-combine-upright-geometry`(38 条断言)、`-modes`(58)、`-wrap`(13)。改动前应是 188 项,我没有单独重跑改前 ctest,这个数是用 191 减 3 推算的。

## 局限

- 只在同一文本节点内合成,跨 `<span>` 的数字不会合成。
- `all` 超过 4 个字符时不合成。
- 垂直居中在 13px 左右会有约 1px 残差,来自光栅取整,没有补偿。
