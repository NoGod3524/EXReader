# Local E1 capture (Windows)

This collector runs headlessly. It builds the current SDK with its default
feature switches in Release and adapts the existing R3 consumer for Windows RSS,
single-CPU affinity and selectable viewport. It does not change SDK sources.
`EXR_BUILD_TOOLS/TESTS/JNI=OFF` omit unrelated executables. The measured DLL still
contains the default SDK features. CMake fails if the R3 viewport patch stops
matching. The generated consumer and compile commands are retained as evidence.

```powershell
cmake -S tools/perf -B evidence/perf-e1-20261107/build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build evidence/perf-e1-20261107/build --target e1-probe --parallel 4
python tools/perf/e1_capture.py --binary evidence/perf-e1-20261107/build/e1-probe.exe --build evidence/perf-e1-20261107/build --font C:/Users/Oscar/exr-deps/reader-font/Reader.otf --output evidence/perf-e1-20261107/baseline
python tools/perf/check_e1.py evidence/perf-e1-20261107/baseline
python tools/perf/e1_capture.py --binary evidence/perf-e1-20261107/build/e1-probe.exe --build evidence/perf-e1-20261107/build --font C:/Users/Oscar/exr-deps/reader-font/Reader.otf --budgets evidence/perf-e1-20261107/baseline/proposed-budgets.json --output evidence/perf-e1-20261107/strict-local
python tools/perf/check_e1.py evidence/perf-e1-20261107/strict-local
```

For the controlled scheduling profile, add
`--priority high --interval 10 --idle-cpu-max 35 --idle-timeout 15` to both
captures. This changes only the native process priority, and records bounded
waiting for lower background load. An unmet idle target remains recorded;
the stability test still decides budget eligibility. Priority belongs to the
environment comparison key. `normalized/` and the independent `candidate/`
used this profile in the retained campaign.

To strictly audit already retained independent measurements, including a
baseline that must be rejected for excessive dispersion:

```powershell
python tools/perf/e1_verify.py evidence/perf-e1-20261107/normalized evidence/perf-e1-20261107/candidate NEW-verification.json
```

This does not recollect or adjust budgets. It checks the prior budget binding,
the environment/source/binary/workload, every raw hash and derived value, frozen
RGBA/text/position signatures, every numeric limit, and final-batch stability.
An ineligible baseline always fails even if all numeric comparisons succeed.
The retained `strict-verification.json` is such a rejection.

Use a new output directory every time. Font provisioning is the existing
`tools/host_font.py` pinned Noto font; retain its OFL license. This machine's
dependency overrides and CA bundle configuration are recorded in
`evidence/perf-e1-20261107/configure-command.json`. Other machines must either
fetch the pinned dependencies or supply their own recorded source directories.
The CA bundle uses Windows' trusted roots; TLS verification remains enabled.

The default fixed input has four 1 MiB chapters, generated by the repository's
deterministic EPUB generator. Each run opens a fresh process on logical CPU 0,
primes file caches beforehand, and measures first frame, 32 sequential requests,
16 seeded random requests, and process working-set high-water. There is no UI,
screen refresh, cold-disk claim, or excluded warmup process. SDK default viewport
is 720×1040 with margin 48; the other two viewports change dimensions only.

`env.json` records CPU, physical/logical cores, reported frequency, OS/build/BIOS,
RAM, compiler/hash/flags, dependency tree hashes, power scheme and processor
policy, battery/AC, hypervisor/SMBIOS evidence, source/protected trees,
binary/runtime/font/tool hashes, and a comparison key. Per-process load snapshots
also record AC, battery saver and OS-reported frequency. These are reported
nominal frequencies, not an effective turbo-frequency measurement. Hypervisor
presence does not by itself establish that the OS is a VM. Unresolved Windows
API-set DLL names are recorded as unknown and tied to the exact OS build.

All statistics use nearest rank. Across three fresh processes, p50 is the middle
value and p95 equals max. Each process's turn p50/p95 is calculated from its own
32 samples, never by pooling pages from different processes. Dispersion is
`100*(max-min)/p50`; population CV is also reported. A complete batch is retried
when any reported metric has dispersion ≥10%, up to three batches. Every earlier
batch, raw stdout/stderr, failure and hash is retained. Reports also summarize
all retained trials, so the final batch does not erase observed noise.

Budgets are derived only from the last complete batch; they are eligible only
when that batch is stable and no process/identity/signature failure occurred.
Latency ceilings use `ceil(p95*1.25*1000)/1000` ms; RSS uses
`ceil(p95*1.05)+1048576` bytes, matching the existing R3 derivation allowances.
Strict local verification checks the frozen environment, source, binary, font,
input and every process in every retained batch against the previously exported
limits. It cannot restore E3 acceptance. Same-environment historical p95 above
1.5× requires manual review. Other environments require separate budgets.

To diagnose existing advisory budget reachability on the frozen eight inputs:

```powershell
python tools/perf/e1_advisory.py --binary evidence/perf-e1-20261107/build/e1-probe.exe --font C:/Users/Oscar/exr-deps/reader-font/Reader.otf --env evidence/perf-e1-20261107/baseline/env.json --archive evidence/perf-e1-20261107/build/frozen-inputs.zip --output evidence/perf-e1-20261107/advisory-check
```

This downloads the existing artifact through `gh api`, checks its registered
source/run/attempt/digest and each input's hash/license, then performs five fresh
processes per input at the original 800×1000/margin 32. It compares native numeric
p95 against all three registered Linux budgets. It omits the final reference PPM
phase and Poppler review, so its RSS covers the timed plan and signature work.
Its cross-environment numeric comparisons grant no acceptance. No workflow is
dispatched by any command above.
