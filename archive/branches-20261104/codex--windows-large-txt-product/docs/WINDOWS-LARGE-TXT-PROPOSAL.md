# Windows large TXT: product gap and SDK proposal

Status: **not fixed**. This branch starts at `b723a9a3a20af7b31729fa1a47b695b20a0c4b8f`. The independent diagnostic at `3dec3f4` contains the evidence and candidate in `docs/WINDOWS-TXT-LIMIT-DIAGNOSIS.md` and `tests/windows_txt_candidate`. Its frozen SDK paths (`src`, `include`, `cmake`, and top-level `CMakeLists.txt`) are identical to this base. The common candidate therefore has the same limit, not a later SDK fix. No product code or protected SDK tree is changed here.

The original full Windows host failed three imports of the 16,792,975-byte sample with `EXR_LIMIT` ([run 40399315487](https://github.com/NoGod3524/EXReader/actions/runs/40399315487)). The diagnostic's public SDK comparison found 131,071 nonempty lines succeed and 131,072 fail ([run 40401376637](https://github.com/NoGod3524/EXReader/actions/runs/40401376637)). The tree requires two root nodes plus a paragraph and text node per nonempty line; the frozen limit is 262,144 nodes. The original error alone does not distinguish the node limit from allocation failure. The independent window consumer scans the sample but its page 28 boundary differs from the whole document, and it does not implement the required catalog, global search, durable anchors, or complete decoding ([run 40404060097](https://github.com/NoGod3524/EXReader/actions/runs/40404060097)). It is not a product fix.

## Interface gaps

* `exr_library_import_source` and its file/unique variants support streaming EPUB/CBZ (and file PDF), not TXT (`include/exr/library.h`, `src/library.c:stream_metadata`). The ordinary TXT import builds a full document, so a Windows adapter cannot use the existing library import to store this input while preserving the original and transactional cancellation.
* `exr_pager_create` requires a complete document to outlive it. The bounded publication pager retains layout continuation and offers normalized offsets and anchors, but the built-in source publication is EPUB-only (`include/exr/layout.h`). Separate TXT documents reset layout at each boundary; `exr_pager_position` is explicitly progress, not a resume token. Public APIs do not expose the continuation state needed to combine those pagers with identical page flow.
* The bounded-pager text and anchor operations apply to its publication part. A TXT adapter additionally needs a whole-book normalized coordinate space and streaming search across boundaries, including matches spanning a boundary. Existing legacy offsets and selectors use normalized document UTF-8 offsets, not source-byte cursors (`include/exr/document.h`).

## Reviewable SDK change proposal

Add an opt-in bounded TXT source route, keeping the complete-document API and its observable node array and limits unchanged. API names below describe the contract and are subject to SDK review; they are not existing functions.

1. Extend source/file library import to accept TXT. Stream and validate using the same decoding and paragraph projection as existing TXT, record a distinct bounded storage mode and normalized extent, retain exact original bytes, deduplicate by original bytes, and commit the row only after successful validation and copying. Honor cancellation throughout and roll back all state on failure. Existing snapshot imports and records remain readable.
2. Add a source-backed TXT publication/pager constructor with explicit workspace, window, page-cache, and checkpoint budgets. It must carry the existing layout continuation across source windows, not treat windows as independent documents. Its normalized UTF-8 positions and paragraph boundaries must equal the existing TXT projection for inputs that fit the snapshot API; source decoding must preserve its UTF-8/BOM and newline behavior, including boundaries inside multibyte characters and CRLF. Return a documented limit for an indivisible item exceeding the unchanged budget rather than truncate it. Keep the original source immutable and define ownership and cancellation at each read and layout step.
3. Expose whole-book bounded text streaming and search with stable normalized offsets, including cross-window matches, plus anchor creation/resolution and replay to an offset. Preserve existing offset-only and quote selectors for unchanged originals; specify missing/ambiguous behavior for changed sources. Bind persisted positions to original identity, and provide explicit migration for existing TXT progress, bookmarks and notes instead of silently reinterpreting offsets. Page replay must reproduce continuous layout with the same font and configuration; positions, not transient window IDs or page numbers, are durable.
4. Integrate Windows catalog/import and reader/search/annotation paths with the new mode through public APIs. Retain ordinary TXT behavior and use the bounded path when needed. Store and reopen the actual original; cancellation or any error must leave neither a partial book nor a modified source.

This needs SDK design and implementation review: in particular the exact API shape, limits for a single long paragraph, decoder semantics, ownership, offset migration, and accounting for all live parsing/layout allocations remain to be settled. No claim is made that an independently implemented host renderer could never reproduce the SDK; the existing public pager does not supply the continuation needed to reuse it as requested.

## Necessary cloud acceptance

On Windows GitHub Actions, run one end-to-end product check using the original-sized deterministic sample, verify its known hash before and after, and exercise import, actual reading across multiple window boundaries, global search including a boundary-spanning match, saved progress/bookmark/annotation and reopen. Record source SHA, original hash, full-process and SDK workspace peaks, and configured budgets. Assert no node or memory budget increase and no body truncation. Include cancellation during import and confirm rollback and unchanged original. Compare manageable fixtures against the existing complete-document path for every page range, normalized text, search and anchors, covering UTF-8/BOM, multibyte splits, LF, CRLF and CR, blank lines and long lines. Exercise existing persisted TXT positions. A failure or unsupported indivisible input must be reported, not replaced by a smaller fixture. These are proposed acceptance criteria, not results from this branch.
