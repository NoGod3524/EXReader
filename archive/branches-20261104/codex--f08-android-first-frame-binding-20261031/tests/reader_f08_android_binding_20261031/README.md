# First catalog Window-frame binding

This adds capture-only evidence to the existing DEBUG/F08_REVIEW + shelf_metrics opt-in. Ordinary startup does not allocate this observer, register a frame callback or request a frame. The original ten UI cases, pre-draw fields, frame records and 2000 ms budget remain.

CatalogShelf arms once after its first real apply/notifyDataSetChanged, only when its attached/shown ListView already requests layout or is dirty. One public Choreographer.FrameCallback latches the primitive adjusted frame time. One main Handler.postAtFrontOfQueue clears the latch after doFrame returns and before another Looper message. No callback re-posts itself. First-ready pre-draw and a passive OnDraw listener must observe the same Window/latch/generation/revision; the OnDraw listener is removed after dispatch. An obsolete first revision remains missing; a later revision never repairs it.

The separate `windows/catalog-ready/window-PID-ID.jsonl` records are recursively collected by the existing adb pull. The original analyzer only scans top-level `windows/*.jsonl`, so its input record contract is unchanged. UI callbacks copy primitives and enqueue records; JSON encoding and new-file I/O run on the existing metrics HandlerThread. The two added public frame fields are `unknown_ns` and `animation_ns`; `callback_mono_ns` uses System.nanoTime. Observer costs remain in the measurements.

The new audit requires exactly one first-ready pre-draw, tree_draw_begin and same-Window FrameMetrics.VSYNC_TIMESTAMP match. It does not join by callback arrival, INTENDED_VSYNC_TIMESTAMP, nearest timestamp, later revision or estimated clock offset. All four nonnegative public intervals UNKNOWN+INPUT+ANIMATION+LAYOUT telescope with INTENDED to native DrawStart in API34. It requires native DrawStart >= tree_draw_begin mono > latched frame time; RT-only frames set DrawStart=VSYNC and fail this bound. Native completion and callback mono must follow DrawStart. Any missing/duplicate/wrong Window/revision/drop/invalid phase is incomplete.

`Window-frame completion upper bound` is `(callback_elapsed_ns - activity_started_elapsed_ns)/1e6`, entirely in elapsedRealtimeNanos. It includes callback scheduling and observer overhead. The mono values only validate the native-frame association. It is not physical presentation or proof of revision pixels; screenshot/actual Window visibility checks remain independent. An upper bound above 2000 ms cannot pass that unchanged conservative check. These controls always report f08_accepted=false.

Public API and API34 reference source:

- [FrameCallback.doFrame](https://developer.android.com/reference/android/view/Choreographer.FrameCallback): public since API16. Direct Choreographer.getFrameTimeNanos is @hide; it is not used.
- [Choreographer API34](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/view/Choreographer.java): postFrameCallbackDelayed puts callbacks in ANIMATION (572); doFrame handles jitter, backwards frames and FPS divisor, stores adjusted VSYNC (743–796), then ANIMATION/TRAVERSAL/COMMIT (804–814). COMMIT may adjust its own frame time later (851–867). CallbackRecord passes the primitive FrameData time (1232–1246).
- [FrameMetrics API34](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/view/FrameMetrics.java): public VSYNC denotes the time used in callbacks/drawing; DURATIONS defines the exact intervals and TOTAL=FrameCompleted−IntendedVsync.
- [ViewRootImpl API34](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/view/ViewRootImpl.java): pre-draw can cancel drawing (3472–3510); dispatchOnDraw (4477) precedes [ThreadedRenderer.markDrawStart](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/view/ThreadedRenderer.java) (734–752).
- [CanvasContext API34](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/libs/hwui/renderthread/CanvasContext.cpp): native completion is recorded before reporting metrics (654–659, 765–773), and RT-only frames use synthetic UI milestone values at VSYNC (800–813). [FrameInfo.h](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/libs/hwui/FrameInfo.h) defines those values (89–103).

Controls run the actual pure Java latch state, compile the observer against the public API34 android.jar, and independently exercise the Python association audit. They do not run an emulator, product benchmark or replace a future same-source cohort.
