## What is implemented

- `fp_core.py`: additions-only source guard against the exact base; run/attempt/source/platform/SDK
  identity; `bind_results` aggregator that flags mixed source or run/attempt, missing platforms and
  failed platforms, and can never set an acceptance flag.
- `fp_maps.py`: fail-closed link-map parsers for GNU ld, lld ELF, Apple ld `-map` and MSVC `/MAP`
  (archive-member selection with non-zero input only); `nm -A -g` archive table parser; the ownership
  policy `audit()`:
  - `sqlite3_open_v2` must have exactly one selected definer and it must be in the installed
    `EXReaderProductCatalog` archive (role `product`); any other selected provider of a `sqlite3*`
    symbol, or a dynamic `*sqlite*` dependency, is a finding;
  - a symbol strongly defined by more than one selected member is a finding;
  - every selected archive must classify to an installed SDK / product / host / system root, else
    `unowned_link_input`; a selected member with no native symbol table is a finding;
  - a non-SDK selected member's undefined symbol that an installed SDK archive defines must be
    resolved by a selected SDK archive member.
- `fp_collect.py`: runs only read-only `nm`/`llvm-nm` and `readelf`/`otool`/`dumpbin` on a real
  built image + map + installed archives and writes `evidence.json` / `result.json`.
- `test_fp.py`: synthetic positive/negative cases (map formats, duplicate/foreign SQLite, wrong owner,
  system SQLite, unowned input, scope escape, mixed-source aggregation). Executed only in Actions.
- Workflow: `protocol` (guard + selftest) and `linux` (unchanged
  `tests/gtk_sdk342_package/run.py build`, then the audit on the real retained GTK host and its
  `gtk-account-host.map`).

## Platform status (honest)

| Platform | Real final-image audit | Notes |

| windows | **not implemented** | MSVC parser + collector exist; no producer emits an MSVC map without editing owner CMake or injecting `LINK`/`/MAP` |
| macos / iphone / ipad | **not implemented** | Apple parser + collector exist; no producer currently passes `-Wl,-map` |
| android | **not implemented** | lld parser exists; map requires an NDK link flag not set by the owner recipe |

Parsers for the four non-Linux formats are exercised only on synthetic text, not on real maps.
Gaps by design: directly linked loose objects (not archive members) are listed but their definitions
are not inspected; the private-header / cross-package include findings of the older Linux auditor
are not repeated here; `final_undefined` is recorded as informational, not judged.

## Interface proposal for the manager (no third-party messages sent)

To make non-Linux maps possible without package-C05 edits, the owners of the Windows/Apple/Android
producer recipes would need to emit a final link map next to the image (`/MAP:<file>`,
`-Wl,-map,<file>`, `-Wl,-Map=<file>`) and keep installed archives unstripped in the retained tree.
Then `auditor collect <config.json>` consumes them (config keys documented in `fp_collect.collect`).

- `libreader_revisions.a(revisions.cpp.o)`: 19 symbols (bind_int, bind_int64, bind_null, bind_text64, busy_timeout, changes, close, close_v2, column_bytes, column_int, column_int64, column_text, column_type, exec, extended_result_codes, finalize, open_v2, prepare_v2, step)

Total 18 + 10 + 19 = 47. Classification: the rule flagged each reference because the installed SDK
archive also defines the symbol and the SDK member was not what the final map selected. That is
a rule defect, not evidence of a wrong provider: the installed SDK ships a vendor SQLite that the
final GNU map does not select. The rule was replaced (not removed): every `sqlite3*` reference must
now have exactly one selected definer and it must be in an archive exported by the installed
`EXReaderProductCatalog` package; any selected SDK/host/other SQLite definer, duplicate definer, or
`*sqlite*` DT_NEEDED stays a finding.

Run 41029510656 (`eb7efb9`) records per-reference evidence from the real map: **83 sqlite3
references, all `resolved_by_selected_product`, each with an unselected SDK candidate (83 of 83)**.
These 83 are a superset of the 47 (every reference, not only those the SDK also defines).
