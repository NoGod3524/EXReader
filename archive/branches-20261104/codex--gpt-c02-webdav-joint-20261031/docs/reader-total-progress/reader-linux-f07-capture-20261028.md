## Retained closure and manifests

The `linux-f07-capture-<run>-<attempt>` upload contains:

- `source.json`: common base, exact source/run/attempt, additions-only path list,
  unchanged producer Git blob and source-scope result.
- `capture.json`: capture state, nested archive size/hash, inventory hash, exact
  final program/raw-tar/F06-ZIP hashes, and explicit `f07_accepted: false`.
- `evidence.zip`: original file bytes under their checkout-relative paths, plus
  `inventory.json` with every size/hash/mode, original symlink target and resolved
  source path (if any), command argv/cwd/status/output paths, final map inputs,
  full native archive list and package identity.

The following exact roots are retained in full:

Original navigation/folder GUI result reports, raw/legacy install/backend logs and
reports, SDK and module build cache,
Ninja/rules/install metadata are included. `commands/` contains final ELF header,
dynamic dependency/symbol tables, global native symbol tables, every captured
archive's member list, and the exact final Ninja command/query output. These are
real native inspection outputs, not producer pass booleans. Directory symlinks or
links escaping the checkout fail closed. File symlinks retain both target bytes
and their original link metadata; they are not recreated when extracting evidence.

The capture requires final GNU map LOAD records to resolve to actual retained
SDK/raw-stage/final-host inputs. Unknown project prefixes and non-system external
link paths fail. Every project LOAD input must be retained. Legacy prefixes cannot
satisfy final-module closure. All files under the three installed prefixes must
exactly match the unchanged builder's installed SHA inventory.

## Independent authentication, not acceptance inflation

The authentication job validates GitHub run/attempt/source/workflow/branch,
successful producer job, upload ID/size/digest and original downloaded upload ZIP.
It rejects missing/duplicate or expired artifacts; safe extraction rejects path,
case/Unicode and parent/file aliases, special members and oversized content.
It rehashes every file, checks the complete installed-prefix inventory, verifies
all original F06 ZIP files and all original unpacked files, verifies the complete
original raw tar against its producer manifest, and binds the final host, raw tar,
F06 ZIP, unpacked program, original build result and entry result to identical
native bytes on this new exact SHA/run/attempt. It rereads the actual final map and
independently runs native `nm`, `ar` and `readelf` on those exact retained bytes.
Every replay invocation and stdout/stderr must match the retained producer command
and output after only replacing the capture-root path prefix.
It never launches a downloaded program, executes artifact-supplied commands,
relinks, installs a package or changes existing F06 assertions.

The original GUI/backend suites remain prerequisite producer steps for successful
authentication. The original GTK authenticator's raw source/legacy-link, navigation
scope and folder scope/zero-failure/source/program identity assertions are explicitly
rechecked against retained original reports; successful step exit alone is insufficient. Capture still preserves completed build closure if a later GUI or
backend step fails; the failed producer cannot authenticate. An incomplete capture
retains its already-copied files in a separately named partial-evidence artifact,
never substituted for the authenticated upload. Their original diagnostics and the normal `f06-linux-<run>-<attempt>` are uploaded
separately. The new independent result means **capture authenticated**, not
“single SDK/SQLite provider proved” or “all modules use only public entry points.”
Those substantive final dependency checks must consume the retained map, archives,
exports and headers in a separate reviewed F07 audit. They remain explicit gaps.
No mainline, PR, tag, release, signing, distribution or six-platform gate is added.
