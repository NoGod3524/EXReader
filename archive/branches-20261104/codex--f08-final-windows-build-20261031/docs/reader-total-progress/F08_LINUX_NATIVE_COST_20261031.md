The test-only module follows the existing native host queue into the SDK worker, retains the exact idle result callback, binds the resulting pixbuf to its accepted page generation, and observes its actual GtkImage draw. It measures worker-pop to corresponding frame after-paint plus a measured XSync(False) fence. This includes actual parse/layout/raster work, UI handoff and queue delay, result application, GTK layout/draw and processing of the preceding X11 connection commands. Native input-to-completion and queue/worker/apply/draw/fence stages remain separate raw fields. The fence changes scheduling; its entire measured wait stays included as a conservative upper bound. This is native server completion, not monitor scanout.

Every submitted job and native frame remains in the census, including non-frame work, superseded generations, missing draws, native errors and background shelf preparation. A missing required visible generation prevents complete evidence. Startup's first page generation is reported separately and remains in the all-page denominator. Page turns, fonts, locate/jump and other reader generations are predeclared groups. Visible shelf worker generations use the same complete boundary. Cached shelf composition reports the conservative native-input-to-completion upper bound, which includes input queue and animation. Reader/body GDK phase observations are labelled separately and never substituted for worker generation cost.

Production sources, SDK, feature flags, 2202-book corpus, original 32+12 launches/760 samples and the separate six causal launches remain unchanged. A synthetic producer injects 50/80ms worker delays and verifies both remain in full cost; removing a completion must retain a missing generation. Full product sampling keeps the original 90-minute job and all original operation timeouts; controls and audit are bounded to 20 minutes each. ## Frozen UI frame boundary

UI duration uses the actual GdkFrameTimings.frame_time to the corresponding after-paint XSync completion. GTK 3.24.33 gdkframeclockidle.c obtains raw monotonic cycle time at line 401. The smooth/clamp branches modify smoothed_frame_time_base, then line 487 stores raw frame_time separately from smoothed_frame_time at line 488. gdk_frame_timings_get_frame_time returns the raw field (gdkframetimings.c line 155). The observer records both the raw timing value and gdk_frame_clock_get_frame_time's animation value, plus its own before-paint monotonic sample. Neither prediction nor smoothing enters duration. Every new raw frame start must independently match the frozen legacy GDK probe by PID/clock/counter. UI update/layout/draw, Cairo/GDK issue and X server processing are included. The Xvfb software profile supplies no physical/GPU/compositor scanout claim.

All frames and maximum duration remain included; the first frame per clock is separately identified by its first observed counter, without a duration threshold. Worker-to-completion and native-input-to-completion remain operation latencies, not ordinary frame duration. A shelf frame that actually composed real content is complete at its native fence even while the logical restore timer is pending; the restore flag and every later composition remain in the raw census. A no-op restore does not invent a missing draw.
