## 实际工作与验收

1. 新增有稳定ID的需求矩阵；每条每平台分别登记 `implemented/exposed/evidenced/manual_pending/missing/blocked`。函数存在、模块通过、实际UI可达、整机体验通过必须分列。
2. 每个已暴露入口记录固定提交URL、文件/符号、界面路径、可见中文标签、处理者及数据落点归属；查不出入口就明确缺失。系统选择器、文件夹、拖放、连线、WebDAV和离线不能互相替代。
3. 每条既有证据记录受测SHA、run/attempt/job、平台/运行环境、原工件及授予范围；检查远端元数据，不把跨源码单平台绿灯拼成六平台通过。过期/缺少工件单列。
4. 人工清单给出干净测试资料、前置状态、准确点击/按键、可观察结果、失败如何保留与恢复。覆盖首次使用、取消导入、重复/损坏文件、账号不可用、离线阅读、同步冲突、重开、记录定位、清空测试资料。不能让测试者使用私人云盘或删除真实书库。
5. Actions 运行矩阵结构/唯一ID/交叉引用/固定提交与相对链接检查；加入最小负例，证明漏平台、伪造通过、无入口的已实现状态、悬空证据会被拒绝。全部数据必须可重新生成，不用空模板计为完成。
6. 最终分开输出“追踪审查完成度”和“产品实际验收完成度”，列清 root 的阻断队列；不凭文档覆盖率算完整产品百分比。

## 执行与证据

本地只读写源码/文档/Git。构建、语法检查、测试、截图、夹具、工件下载/解包/解析全部只在 Actions；禁止 cpuse。允许独立分支提交、push、触发/修复Actions，无需再问push；禁止default分支、合PR、tag/Release、签名或改保护规则。

工作流守卫固定起点祖先、HEAD==GITHUB_SHA、独占路径及全部保护树；记录审查工具源码身份和每个被审目标身份。汇总在Actions下载同source/run/attempt工件，核对作业success、唯一名称、非空大小、digest、有效期、ZIP重算、报告/矩阵散列；拒绝错身份/缺项/重复/篡改。原始API响应和链接结果保留，日志不含凭据。纯文档封存使用 `[skip ci]`。
