Measured horizontal merge (merge.ppt)
The group remains at 00036508; F122 remains at 00036570 with 039F=1 and
the same 14-byte C3A0 array. ClientAnchor moves to 00036C95, values unchanged.
The upper-left cell F004 @00036CA5 / F00F @000370D4 expands to
(480,640,3360,1360). The covered upper-right cell shape is absent.
Only three cell rectangles remain. The internal vertical border F00F
@00037ED5 becomes (1920,1360,1920,2080), covering the lower row only.
There are still six border line shapes. No separate merge-start/covered-cell
flags are stored in this representation; spans and coverage follow geometry.

Record identification and limits of inference
- No table-specific ClientData instance, TableRow or TableCell records occur
  in the measured table group. Its shapes do not require F011 ClientData.
- 0F9F is TextHeaderAtom, not a Table record. F122.recInstance=3 counts
  property entries; 039F bit 0 identifies this group as a table.
- Columns are inferred from cell anchor boundaries. If every row merges
  horizontally across the same hidden columns, their original count cannot
  be recovered from these OfficeArt records alone.
- Row heights are minima; wrapped text can make actual rows taller. Actual
  visible cell boundaries take precedence. The implementation interpolates
  from valid minima only when all internal row boundaries are invisible.
  Partial invisible row boundaries can leave row counts approximate and warn.
- Rendering uses normal M2 shapes/borders and M4 text. The implementation
  bounds the recovered grid at 200 rows by 200 columns, keeps the first
  rectangle on conflicting coverage, and suppresses internal borders in
  covered spans. It does not invent alternate record types or merge flags.
