# 根因：调度等待与 p95 的组合

主导因素是**同核时间片争用**。参照与翻页的执行组成确实不同，但本次对照中，它们的实际执行成本变化远小于墙钟变化；频率下降不能解释主要偏移。`diagnosis/` 是独立的三档各一轮诊断，不参与五轮预算定线。

同一 #87 SDK、同一逻辑核 CPU 3、HIGH priority、AC min=max=100/boost=0。压力分别是 0/1/3 个同优先级、同核整数忙循环。每档均完成 19 本书 × 16 个顺序翻页；首屏另存且排除。所有页、RGBA、文本和位置签名相等。

墙钟的大部分增加没有对应的线程执行周期。按全部目标窗口汇总，`线程计入周期 / elapsed TSC` 从 **0.9873 → 0.5257 → 0.2545**；参照从 **0.9870 → 0.5253 → 0.2513**。两者平均获得的 CPU 份额相近，但把不同长度窗口分别取 p95，再相除，会把时间片分布的差异带进比值。不同书的工作时长、跨章节边界和恰好发生的抢占，使偏移方向与幅度不固定。

本次长参照复测的墙钟漂移是 −6.17%/−3.35%，没有重现 #87 的精确 −17%。#87 的原始数据只有墙钟；这里的归因来自新增计数器的同机对照，正式达标判断使用后续三档各五轮。

## 三条假设的判定

1. **组成不同：结构上成立；不足以解释主导偏移。** 反汇编中参照的循环每轮只有 `movzbl/add/xor/imul/cmp/jne`，没有循环内 load/store；120,000,000 轮约执行 720,000,000 条循环指令。这是静态循环计数，非 PMU 测量。目标的线程周期约 **47.85% / 48.10% / 48.12%** 花在排版与跨章节准备，其余是渲染。受压后执行成本的差异为 +4.40%/+1.39% 的 ratio 残差，没有墙钟的 2–4 倍增长。没有目标 retired-instructions 数据，不能把剩余误差进一步分摊为 IPC、分支失误和内存等待。
2. **降频：未成为主要原因。** CPU 3 的三个在载遥测样本，各档 `ProcessorFrequency` 均为 2200 MHz；`PercentProcessorPerformance` 分别为 94/94/94、94/93/93、94/94/94，`PerformanceLimitFlags` 均为 0。更密集的固定参照线程周期在 304 次窗口的 p95 上只变化 0.06%/0.10%。这些数据不支持用降频解释 +102%/+310% 的参照墙钟变化。
3. **加压进程污染 L3：未证实为主因。** 压力程序的循环工作集在寄存器中，没有大数组或带宽访问；本机没有配置 PMU 的 LLC/分支事件。目标增加的执行周期可包含缓存、其他后台工作和计数器开销，现有数据不能分别量化它们。不能据此声称缓存影响为零。

## 计数器边界与可解释范围

`QueryThreadCycleTime` 返回线程被计入的 CPU 周期，包括 user/kernel；实现依赖 CPU，**不转换为毫秒或 unhalted-core IPC**。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-querythreadcycletime)

TSC 用作 elapsed ticks 和计量覆盖核对，不作为 retired instructions，也不用于推断实际核心频率。现代 invariant TSC 可在频率改变时保持固定速率。[Intel 手册](https://cdrdv2-public.intel.com/868137/325462-089-sdm-vol-1-2abcd-3abcd-4.pdf)

`EnableThreadProfiling`/`ReadThreadProfilingData` 的 dispatch 数据可用，但 `HwCountersCount=0`、全部硬件计数器值为 0；配置硬件事件需要驱动。因此没有伪造目标指令数、IPC 或 cache-miss 数据。[Microsoft API 说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-enablethreadprofiling)

两个仪表试跑完整保留：第一个漏计 R3 已计入墙钟的跨章节工作；第二个因独立时钟边界中间被抢占，产生约 15.9 ms 的边界偏差。正式探针使用一致的 QPC/TSC/线程周期快照，覆盖 EOF、建 pager、排版和渲染；读取中发生切换只重读时钟快照，不重跑翻页。守卫没有放宽，三档诊断的所有已纳入样本均通过覆盖检查。

修正选择：采用完整目标的线程周期，配对前后固定参照的几何均值，消除等待调度的影响并减小前后状态变化。它度量 CPU 工作成本；线程阻塞导致的用户可见等待继续由原始墙钟呈现。这个指标不能单独替代独占 runner 上的墙钟延迟检查。
