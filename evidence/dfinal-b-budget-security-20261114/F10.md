## 生产修复

`examples/windows/shell_sync.inc:127` 新增 `sy_cred_recover_temp`，由真实同步初始化 `sy_init` 调用（壳通过 `sy_ensure` 惰性初始化同步，并非程序启动时无条件扫描）。只检查固定的 `<data>/sync.cred.tmp`；独占打开同一对象后，验证普通文件、非 reparse point、单硬链接、当前用户 owner、protected DACL，且只有当前用户和 SYSTEM 两个精确的 FILE_ALL_ACCESS ACE。满足全部条件才用同一句柄的 `FileDispositionInfo` 删除，避免按路径检查后再按路径删除的替换窗口。正在写入的文件、目录、硬链接及宽权限占位全部保留并返回失败。

本轮没有泛扫临时目录；旧版继承 DACL 或其他 owner 的残留无法获得这一恢复授予。私有 writer 的安全描述符同时显式设置 TokenUser owner，避免提升权限的 Actions runner 默认 owner 为 Administrators（旧 `actions-final/new-checks.txt:71` 输出 `O:BA`）而不能识别自己新建的 stage；测试现在断言 owner 与 TokenUser 精确相同。正常私有写入仍先设置保护 DACL、独占 CREATE_NEW，然后写入/flush/原子替换。Credential Manager 接入、会话回退和旧已保存凭据权限迁移仍缺。

`check_sync.c` 只在测试入口定义 `EXR_READER_SYNC_TEST_DRIVERS`；测试 hook 在生产 private writer 完成 FlushFileBuffers 后通知父进程并等待。父进程实际 `TerminateProcess(...,77)`，随后调用生产 `sy_init`，断言私有 stage 消失、旧凭据仍能加载、后续保存成功。普通产品编译不包含 hook。
