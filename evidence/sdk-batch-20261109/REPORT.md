# S1：SDK 连续批量路径性能

最终候选采用 **8192 槽、四路组相联整形缓存＋2MiB 字形位图 LRU**。在《紅樓夢》、指定字体与版式、预热前21页和受控Windows电源策略下，五轮20次同步翻页的 p95 为 **14.8688, 14.9382, 15.0047, 14.7733, 15.0419 ms**，全部≤16ms；离散度 **1.799619%**，小于10%。无预热同配置 p95 为 **26.0109–26.6201 ms**，未达16ms；本次达标条件包含显式预热。

## 测量口径

- 书籍：`hongloumeng-24264.epub`；字体：`../exr-demo-2a/Reader.otf`。
- 最终测量SDK DLL SHA-256：`c308aca22f3504fb238d3696c7e7ea4adf466f4de05f675ca43964a24abf68b6`。
- SDK正文1552×928，margin48、font24、line-height1.5、paragraph-spacing10；文档CSS和嵌入字体采用SDK默认值。
- 每轮重新打开字体和publication，先记录首屏，再记录第1至20次连续翻页。与#103相同，计时范围是 `exr_pager_next()` 到 `exr_render_page_color()` 返回，包含分页、整形和完整RGBA光栅输出。没有后台准备线程或已渲染帧队列。
- 首屏单独保留；打开字体/书籍、章节加载、pager创建及显式warmup不计入翻页时长，均单独记录。所有样本原样保留，无重试或样本剔除。
- p50/p95使用nearest rank：20个排序样本分别取第10/19个。五轮离散度=`100×(最大p95−最小p95)/平均p95`。
- 最终[受控会话](controlled-2/session.json)：CPU3进程亲和性、HIGH优先级，AC处理器最小/最大100%、boost0；前后各采集3个环境样本。脚本使用保存的scheme GUID，并在 `finally` 恢复及读回核验。

最终会话电源恢复核验：`verified=true`；原scheme `381b4222-f694-41f0-9685-ff5bb260df2e`，恢复AC `min=5, max=100, boost=2`。见[恢复记录](controlled-2/power-restored.json)。

最终五轮批次在本地11:18:40前完成；因postflight的CIM采集迟缓，在11:22:04按保存的原策略[提前恢复电源](controlled-2/power-restored-early.json)，再开始最终回归。该会话postflight与后续测试重叠，不作为测量期间的环境记录。wrapper已调整为先恢复电源、再采集postflight，避免环境记录延迟恢复。

## 根因与修改

起点是main **b0af2a55**。用户引用的[#103](https://github.com/NoGod3524/EXReader/pull/103)（**7253ca1ad014baa5fa516aeacf4f15b6829ded3f**）尚未合入这个起点，所以先移植其中SDK字形位图缓存、短整形缓存、灰度混合优化及整形一致性测试；没有引入其宿主UI修改。

#103的44.1758ms轮次完整序列如下，保留来源路径、源文件SHA-256及20页像素hash于[historical-103.json](historical-103.json)：

```text
3.2033, 6.3613, 17.5274, 16.4051, 13.2451, 11.8610, 12.2265, 44.8557, 43.4210, 41.9528, 34.7577, 10.5684, 12.1346, 8.7758, 8.5452, 42.8419, 44.1758, 12.9009, 9.3921, 10.6542
```

尖峰在第8–11和16–17次，也出现在已经较快的页面之后，因此历史不稳不能归结为“最初几次冷、之后一直快”。早期16.08ms整形数据属于更早基线；#103最终44.1758ms样本中，分页/整形4.9970ms、光栅/输出39.1788ms。实际连续路径为单线程同步调用，无批量内部worker或锁争用。

缓存计数揭示了另一部分可修复成本：1MiB字形缓存和1024槽直接映射整形缓存，即使预热后仍发生1317次字形淘汰、7200次整形淘汰。扩大到2MiB/4096后，字形命中100%，整形仍因槽碰撞发生2779次淘汰；4096四路组相联降至1091次，最终8192四路降至123次，预热后整形命中99.664576%。容量和组内MRU替换共同减少重复工作。

自由电源策略下，4096四路预热五轮均低于16ms但离散度20.754057%，仍判失败。受控AC策略下同版离散度降至5.757753%，p95仍有16.6864ms，仍判失败。保持相同受控协议后扩至8192槽，五轮同时满足延迟与离散度目标。环境控制用于收敛测量波动，缓存修改用于减少实际同步计算成本。

新增公开接口：

```c
exr_publication_warmup(publication, font, &config, pages, &error);
exr_font_cache_stats_get(font, &font_stats, &error);
exr_pager_cache_stats_get(pager, &pager_stats, &error);
```

warmup同步预热前N页，复用同一字体和版式；缓存有界，不改变阅读游标，支持配置中的取消控制。嵌入CSS字体属于临时pager，其缓存随pager释放；这些书籍需要保留实际pager并使用 `get()` 预备页面。未增加`src/*.h`，新增 `src/warmup.c` 已登记到 `tools/layers.json` 的render层。

## SDK用户复现

[bench_batch源文件](../../examples/bench_batch.c)使用公开SDK API。构建、输入参数、旧SDK基线模式及完整受控协议见[用法](../../examples/bench_batch.md)。独立MinGW编译：

```powershell
gcc -std=c11 -O3 -Wall -Wextra -Wpedantic -Werror `
  -I include -I build/s1-after/generated/include examples/bench_batch.c `
  -L build/s1-after -lexreader -lshell32 -o build/s1-after/bench_batch.exe
```

仓库CMake目标为 `bench_batch`；已安装SDK可独立配置 `examples` 工程并构建 `exreader-bench_batch-example`，产物同为 `bench_batch.exe`。

最终会话命令（输出目录必须不存在）：

```powershell
pwsh -File tools/perf/batch_session.ps1 `
  -Binary build/s1-after/bench_batch.exe -Reference build/s1-103/bench_batch.exe `
  -Book ../exr-cjk-corpus/hongloumeng-24264.epub -Font ../exr-demo-2a/Reader.otf `
  -Output evidence/sdk-batch-20261109/controlled-2 -Cpu 3 -Runs 5 -Turns 20 -Warmup 21
```

`--json`输出包含20次逐页layout/render/total、三组缓存计数、p50/p95、首屏和预热耗时。`passes`要求至少5轮×20次、每轮p95≤16ms且离散度<10%；程序退出码表示执行或输出是否出错，数值失败仍保留输出。
