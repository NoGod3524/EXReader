# P 包 CI 卫生清单

适用：固定基线准入及 Apple 共享 provider 负例 harness。不进入 F07 已知问题清单。

- 固定基线比较前必须取得完整所需历史，并用 `git cat-file -e <base>^{commit}` 确认对象可读。CI-ADMISSION-001 已有本地浅克隆和远端准入通过证据。
- CI 禁止裸 `test -n`。空值失败必须打印“期望什么 / 实际得到什么”以及候选文件路径，然后明确退出。
- 不把 FetchContent 的普通变量当成必然存在的缓存键；构建期间显式导出所需源码路径及其 hash，读取时核对来源。
- 负例必须显式断言预期失败，打印被拒绝对象的路径和实际错误信息；缺依赖、输入为空、工具失败不得计为成功拒绝。
- 单命令负例使用以下退出码包装；还须匹配预期的实际拒绝信息，不能只凭任意非零认定通过。

```bash
set +e
<cmd>
rc=$?
set -e
[ "$rc" -ne 0 ] || { echo "control did not fail"; exit 1; }
```

聚合 Python harness 可捕获预期异常、核对精确拒绝原因并正常退出 0；实际错误信息必须同时打印到作业日志并写入结果文件。
当前 `check.py` 已有精确异常核对，但只把单例拒绝信息写文件；不能用缺少日志来替代拒绝证据。

本次仅立规则，不改 workflow、检查器或测试断言。负例验证未完成仍为 **R 前阻断项**，不得作为普通 open item 延后。
