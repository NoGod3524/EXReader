## What this adds beyond module-only F05
The native `reader_f05_closure` drives installed modules through a child-process consumer. This package drives the
**actual GTK host binary** (`exreader-linux`), through its native controls only (import chooser, Book details, Account and
Sync), as two independent profiles ("peerA", "peerB") against one native-HTTPS WebDAV fixture with a verified certificate.

Flow (one Linux runner, one source, one attempt):
1. peerA imports a TXT, saves a title, connects, scans: the fixture records the real PUTs; wire bodies equal peerA's history.
2. peerB, an empty profile, scans and obtains that history **only** by GET from the fixture (no PUT by peerB, no copying).
3. peerB imports the identical original; both peers make distinct offline children of the same received head.
4. peerB scan is gated at a real PROPFIND and cancelled with the Cancel control; remote unchanged, outbox pending.
5. Retry: the fixture reads half of the revision PUT body then resets; nothing stored, failure visible.
6. Retry: the fixture commits the PUT, withholds the response; the host process is SIGKILLed.
7. Same profile restarts and rescans: one wire object, one local row, outbox acknowledged (idempotent).
8. peerA then receives peerB's sibling (two heads, `projection_safe` false, local title untouched), pushes its own;
   peerB pulls it; both converge on identical heads/history equal to the wire.

Local product databases are opened read-only (`mode=ro`) and through the installed revision consumer's `heads` query.
No revision, outbox or remote entry is inserted by the test. `database_planting` is recorded `false`.

## Interface findings for the manager (not implemented here)
* Hosts only drive `reader_session_start/cancel` from the Account dialog (GTK `examples/linux/accounts_ui.inc`, Windows
  `apps/reader/desktop/windows_accounts_ui.inc`); the in-window sync view is read-only. No host exposes conflict
  resolution, tombstone/delete or an explicit "sync now" API a test could call without UI automation.
* A Windows or macOS/iOS/Android equivalent needs a per-platform UI driver; none is attempted. The Windows host paths are
  owned by native agents and were not touched.
* Proposal: a production-owned, test-visible fixed-name state dump of `reader_session_snapshot` per host (GTK already
  writes `state.ini`) would let other platforms bind the same assertions.

## Not claimed
Linux GTK only; no six-platform pass, no Windows/Apple/Android host, no receive/import cancellation, no delete-versus-update
or tombstone restore proof, no physical device or real user cloud, no performance claim. This is not full P0 and does not
change the 95/108 acceptance count.

## Remaining deficiencies
The audit shares authorship with the harness, so it is a source/identity authentication, not an independent oracle.
Linux GTK only. Not covered: Windows/Apple/Android hosts, delete/tombstone, receive/import cancel and crash, two live
hosts at the same instant (peers are driven in alternation on one display), real user cloud. The fixture is a controlled
loopback server, not an arbitrary WebDAV implementation.
