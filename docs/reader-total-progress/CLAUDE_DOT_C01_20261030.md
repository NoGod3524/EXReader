## What "full49" means here
The native `wr_identity` text is 48 lowercase hex plus NUL (`char[49]`, see
`wr_identity_text`; M09 in `WINDOWS-P0-FAULT-20261030`). The lease key is that whole text:
uppercase, shorter, longer or non-hex input is `LM_WL_INVALID` and creates nothing. Two
identities sharing the first 32 hex and differing in the last 16 get different lease files.

## Mechanism (absent from the observer engine)
One file `<identity48>.lease` (72 bytes: magic, identity binding, 8-byte generation) in a
caller-owned private lease directory.
* **Lock**: `LockFileEx` byte 4096, shared or exclusive, `FAIL_IMMEDIATELY` + bounded poll.
  Locks are per handle, so they exclude other processes *and* other handles in one process.
  The kernel releases them on process death (verified with `TerminateProcess`).
* **Handle lifetime**: file and directory are held open without `FILE_SHARE_DELETE`, so the
  lease file cannot be deleted/renamed/replaced and the directory cannot be moved while any
  holder lives. Lease lifetime = handle lifetime, not file presence.
* **Fail closed**: reparse/directory/extra-hardlink/size-mismatch/foreign-header lease files,
  a reparse lease directory, or a file that is not directly inside the pinned directory
  (final-path check) are `LM_WL_REFUSED`; contention is `LM_WL_BUSY` (never auto-retried
  beyond the caller's `timeout_ms`).
* **Crash-safe intent (follow-up)**: the lease file is 80 bytes: generation at 64, pending at 72.
  The exclusive holder calls `lm_wl_exclusive_begin` (persists PENDING) before its first
  irreversible step and `lm_wl_exclusive_commit` (generation+1, then clear PENDING) only after
  its own full verification of the published result. If the holder dies anywhere between, PENDING
  stays set: every shared acquire returns `LM_WL_STALE` (no lease granted) until an exclusive
  holder re-qualifies and commits. The lease does not observe the rename, so it cannot say whether
  publication happened; it only refuses admission to an unacknowledged one.
  `lm_wl_exclusive_bump` was removed (it was the missed-bump gap).
* **Admit-reopen gate**: generation counter at offset 64. Admission records
  `lm_wl_generation()`; reopen re-acquires shared and calls
  `lm_wl_require_generation(lease, admitted)` -> `LM_WL_STALE` if the publisher bumped.

## Coordination contract proposed to native publisher/observer owners
No edits were made to their files. Proposal only; nothing here is agreed until the manager
confirms.
1. **Names**: lease directory is a private directory chosen by the migration host
   (suggest sibling of the wr_context private root, same ACL policy); file name is exactly
   `<wr_identity_text(target)>.lease`. The lock offsets 4096 (lease) / 4097 (init) are reserved.
2. **Shared** (reader/host admission): acquire `LM_WL_SHARED` with the target identity before
   reopening/using published data; keep the lease for the whole use; `lm_wl_check` before each
   trust decision; release on close.
3. **Exclusive** (publisher): acquire `LM_WL_EXCLUSIVE` *before* `lm_wp_publish*` and keep it
   across rename and record write; call `lm_wl_exclusive_begin` right after acquiring and
   `lm_wl_exclusive_commit` only after full verification of the result, then release. If publisher already holds shared there is **no upgrade**: release, then take
   exclusive; any other holder yields `LM_WL_BUSY`, which the publisher must treat as
   refusal (no force, no break-lock, no retry loop beyond its declared timeout).
4. **Errors**: `OK`, `INVALID`, `BUSY`, `STALE`, `REFUSED`, `NATIVE` (+Win32 code), `LOST`.
   `STALE`/`LOST`/`REFUSED` -> stop and re-qualify; none implies rollback or completion.
5. Crash: a dead holder auto-releases. Death between begin and commit leaves PENDING, so shared
   admission fails closed (STALE). Resolution is an exclusive acquire, re-qualification by the
   owner of the published data, then commit; the lease does not decide that for them.
6. The lease never grants SDK admission, migration commit or acknowledgement.

## Known limitations / deficiencies
* Not integrated with `lm_wp_*`, the recovery engine or host; no installed consumer proves
  publisher+lease in one flow. The integration order in (3) is unverified.
* The missed-bump gap is closed fail-closed (begin/commit), but the lease still cannot tell
  whether the rename happened; observer/record remain the authority. A crash that leaves PENDING
  blocks shared admission until explicitly resolved (availability cost, by design).
* Custody boundary: the publisher at c45d01c8 has WR_RECORD_MAX = 1 MiB and its opaque
  `lm_wp_custody` is not a `wr_context`; after `wr_close(original)` `lm_wr_record_write/read`
  cannot use it. The lease touches neither (it takes only a directory path). No bridge, cast or
  reopen of frozen parent pins is made or claimed; any such bridge needs separate qualification.
* Local NTFS only. SMB/network, power loss and directory-fsync equivalence are not claimed.
* Per-lease object is single-threaded. Lock offset 4096 beyond EOF is a convention; a process
  that does not use this library can still open the file (it cannot delete it while held).
* No ACL is applied by this library; the caller's private directory must provide it.
