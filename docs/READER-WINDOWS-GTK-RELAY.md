四阶段依次使用真实宿主：Windows 导入并上传原件；GTK 接收并通过公开 SDK 读回该原件，
在界面创建标签及成员，并上传自己的原件；Windows 接收并读回 GTK 原件，在原生界面移除
该成员、确认批量回执并上传另一原件；GTK 在界面确认成员已移除并通过公开 SDK 读回新原件。
四阶段检查名由汇总固定；上传的两份程序由汇总重新散列，并与阶段及保留回归报告比对。
Windows 构建保留检查、GTK 当前 48 项和原版 46 项接收回归在同轮通过。

每个 runner 启动独立的本地认证 TLS WebDAV 服务；阶段间通过 Actions 工件传递服务条目，
逐条验证 SHA-256、已有条目不变及快照前后链接。这是**服务状态接力**，没有测试两个宿主
同时连接同一个在线服务，也不代表 Android、Apple 或六平台互通通过。受测 Windows 宿主使用
raw 修订家族，GTK 使用 legacy 家族。受测基线的 Windows 界面只能操作已有分组；标签由 GTK
实际创建，没有把公共命令生成的分组当作 Windows UI 操作。

ID `12697923752`、`12699550949`、`12699318210`、`12699635895`。汇总记录各工件 digest。
