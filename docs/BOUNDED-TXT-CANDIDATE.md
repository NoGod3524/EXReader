# Bounded TXT candidate: projection stage

This is an incomplete SDK candidate based on b723a9a3a20af7b31729fa1a47b695b20a0c4b8f. The opt-in `exr_txt_scan_source` streams an immutable source into paragraph callbacks using whole-document projected UTF-8 byte offsets. It decodes BOM-marked UTF-16 and UTF-8, normalizes newlines, trims and omits empty paragraphs as the snapshot parser does, handles short reads and cancellation, and rejects an indivisible decoded line above 64 KiB. Callbacks can have already run when an error is returned; callers must discard their own partial state. This primitive does not retain the source or establish its identity.

The Windows workflow exercises the installed API against small snapshot projections, short reads, encoding errors and cancellation, and scans the diagnostic's original deterministic fixture with hash checks. This is a projection test, not product acceptance or a memory-budget measurement.

Remaining work: transactional source import with distinct storage mode and original-byte identity, complete continuous bounded layout and page replay, whole-book search, persisted progress/bookmark/annotation anchors and migration, Windows integration, and full end-to-end budget and compatibility acceptance. In particular the scanner alone does not resolve the measured independent-window pagination mismatch. Existing snapshot APIs and product paths remain unchanged.
