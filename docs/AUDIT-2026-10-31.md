## F01 P1 批处理错误路径重复释放并终止进程

位置：`tools/convert.c:664–668`。

重复输出检测中，`cv_same_file()` 失败后先在分支内释放 `local_error`，随后又无条件释放同一指针。已经在预检中被拒绝的任务仍然进入这段循环，因此一个非法输出路径加一个正常任务即可触发。

隔离复现中，非法路径单项正常返回退出码 3；将它放入双项批处理后，进程在预检阶段异常终止，没有 JSON 结果，正常任务也未执行。这违反了单项失败后继续处理独立任务的转换契约。

修复：让该错误对象只有一个释放点，并保留明确的任务拒绝结果。回归应同时验证异常项、独立正常项和最终报告。

证据：`build/audit-20261031/converter-final/converter-probes.json` 的 `invalid_path_single`、`invalid_path_batch`，以及对应子目录。

## F02 P1 保存进度或收藏使已打开的 CBZ 无法继续读取

位置：`src/library.c:536–541`；读取点 `src/library.c:261–265`；更新点 `src/library.c:632–644`。

`exr_library_fixed_source()` 将同一数据库连接上的长期 SQLite blob 句柄交给 CBZ 阅读器。`exr_library_update()` 更新 `books` 中同一行的进度、标题或收藏时，这个 blob 句柄失效；后续 `stream_blob_read()` 仅把读取失败转换成零字节，没有恢复句柄。

使用仓库原有 `comic.cbz`，公开 API 的结果如下：

| 操作 | 结果 |
| --- | --- |
| 流式导入、打开并渲染 | `EXR_OK` |
| 保存阅读进度 | `EXR_OK` |
| 用原阅读器再次渲染 | `EXR_IO` |
| 重新打开阅读器并渲染 | `EXR_OK` |
| 保存收藏，再用该阅读器渲染 | 更新成功，渲染 `EXR_IO` |

因此，按页保存进度的宿主会在正常阅读过程中使当前书籍失去可读性。此问题来自数据库读取句柄，原书内容没有损坏。

修复：让源适配器保留稳定书籍 ID，在 blob 因元数据更新失效后重新打开并校验原书；补充“打开、渲染、更新进度或收藏、继续渲染”的公开 API 回归。

证据：`build/audit-20261031/probe_library.c`、`build/audit-20261031/library-probe.log`。探针仅使用公开 SDK 与独立临时数据库。

## F03 P2 Unicode 大小写别名绕过批处理重名保护

位置：`tools/convert_io.c:121–127`；调用点 `tools/convert.c:661–672`。

Windows 路径比较使用 `_stricmp()` 比较 UTF-8 字节。它能处理 ASCII 大小写，却不能匹配文件系统对非 ASCII 字符的大小写规则。两个目标尚不存在时，没有现有文件 identity 可以补救这一遗漏。

在默认大小写不敏感的 Windows 目录中，两个不同输入分别输出到 `É.txt` 和 `é.txt`，启用覆盖后两项都返回 `ok`，整批退出 0；实际只有同一个文件，内容属于第二项。第一项报告的输出 SHA-256 与最终文件不符。对应 ASCII 大小写对照会正确拒绝两项。

修复：在 Windows 路径比较中使用 Unicode 宽字符比较，并继续结合父目录解析与文件 identity。新增尚不存在目标的 Unicode 别名回归，同时检查最终文件散列与报告一致。

证据：`build/audit-20261031/converter-final/converter-probes.json` 的 `unicode_duplicate` 和 `ascii_duplicate_control`。前者记录 `outputs_are_same_file=true`、`output_hash_matches_report=[false,true]`。

## F04 P2 报告可以在未授权覆盖时替换批处理清单

位置：`tools/convert.c:1107–1118`；写入点 `tools/convert.c:1099–1100`。

`report_collides()` 只检查任务的输入和输出，没有把批处理清单纳入保护集合。报告发布又始终采用覆盖模式。因此，将报告路径设为正在读取的清单路径，会在未使用 `--overwrite`、清单默认 `overwrite=false` 的情况下，以报告替换清单，并返回成功。

复现后，原清单散列变化，文件变为包含 `tool`、`engine_version` 等字段的结果报告，不能再作为原批处理配置使用。

修复：将清单本身及其文件别名纳入受保护输入集合，在任何报告或转换结果发布前拒绝冲突。

证据：`build/audit-20261031/converter-final/converter-probes.json` 的 `manifest_report`，以及同名目录中的最终清单与标准输出报告。
