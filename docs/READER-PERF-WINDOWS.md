## 测量口径

每次样本都是一个独立的新进程：`EXReader.exe --font Reader.otf --data <profile>`。
所有操作由外部观测者投递到该进程真实存在的 Win32 控件上，并从同一控件读回结果：

| 操作 | 原生输入 | 观测点 |
| --- | --- | --- |
| 首屏可交互 | `SendMessageTimeoutW(WM_NULL)` 到主窗口 | 产品书架页 50 行已交付（详情按钮已由 product_ready 启用、行文本不再是旧 SDK 列表格式）且 UI 线程完成一次同步消息往返 |
| 书架分页 | 列表 `WM_MOUSEWHEEL` 滚到底部 | 列表由 50 行增至 100 行（keyset 下一批） |
| 搜索 | 搜索框 `WM_SETTEXT` | 列表变为该过滤条件的 50 行结果（含宿主 200 ms debounce） |
| 打开书籍 | `LB_SETCURSEL` + 打开按钮 `BM_CLICK` | 页码标签首次出现合法页号 |
| 书内翻页 | 下一页按钮 `BM_CLICK`（每次启动 8 次） | 页码标签页号/章号发生变化 |
| 继续阅读 | 新进程启动（宿主自动恢复上次书与页） | 页码标签恢复到上次页号，并与上一进程逐次比对 |
| 导入期间输入响应 | 导入按钮 `BM_CLICK` 后持续采样 | 导入忙窗口内 `WM_NULL` 往返与路径框回显 |
| 工作集峰值 | 观测进程每 20 ms 读一次 `GetProcessMemoryInfo` | `PeakWorkingSetSize` / `PrivateUsage` |

这些消息投递到真实原生控件并由产品 UI 线程处理；不是 `SendInput` 级别的硬件注入。
上报值是**外部端到端 UI 延迟**。**帧时间未测**：该路径没有暴露应用内帧或 present 信号，
任何数值都不能称为应用帧时间，也不代表「丝滑」。

冷/热：冷启动组每次从种子库文件复制全新 profile（无目录库、无 `host.ini`），每次重建
产品目录；热启动与阅读组复用已建 profile。磁盘缓存与同宿负载不受控，冷/热只描述
profile 策略。两轮的绝对数值差异（如冷启动 5.13 s 与 2.72 s）来自不同 runner 的
CPU（EPYC 7763 与 9V74）与负载，本包不据此比较优劣。

## 原 TXT 路径追查（第二轮核心）

第一轮记录原 16 MiB 单文档 TXT「导入后不可见」后换用了 EPUB 夹具，那只能作为独立样本，
不能为 TXT 路径背书。第二轮在同一源码上按冻结参数**逐字节重放原输入**，并把事实分开记录：

输入身份：`format=TXT`、`declared_size=16 MiB`、首行 `Perf Import %04d`、每块 512 行、
单位 40,465 字节；**实际 16,792,975 字节**，SHA-256
`4f45393b25817f506a51b56cc5d61599556e4dd5b0bd59aa00f7eb43cbfc0a86`。
输入预期：导入成功、书架可见、标题为文件名 stem（宿主的 Untitled 回退）、源字节与 SHA
与输入一致。

三次独立启动的事实（逐次一致）：

- 真实 Win32 导入：路径被接受，导入在 225.1 / 204.7 / 224.8 ms 内结束（按钮恢复），
  未触及原 300 s 等待预算，不是挂起；
- 状态（逐字）：`导入失败：超出宿主或SDK限制（Native parser failed (6)）`
  （`EXR_LIMIT` = 6）；
- 书架查询（真实搜索框，四个 needle 各自记录）：`Perf Import 000?`、`fixture 000?`、
  `Perf import`、`Untitled` 全部 **0 行**；
- 产品目录：`reader_books` 无该 SHA 行、`reader_local_books` 无映射，总数仍 **2202**；
- 公共 SDK 原件核对：失败后点击产品「刷新」触发修复任务（该任务枚举公共 SDK 书库并
  补挂），刷新后仍无该行、目录仍 2202 → SDK 中没有遗留原件；
- 打开：无可见行，未发起打开。

判定：**真导入失败**——SDK 文档模型对单文档 TXT 的限额。不是「首行派生标题导致过滤
不命中」（`Untitled` 与 stem 两个 needle 都试过），也不是就绪等待或性能问题（导入只
用了约 0.2 s，远低于等待上限）。

边界（同源一次启动内逐级导入同一行结构）：

| 声明大小 | 实际字节 | 文本行数 | 结果 |
| ---: | ---: | ---: | --- |
| 0.25 / 0.5 / 1 / 2 / 4 / 5 / 6 / 6.5 MiB | 286,880 … 6,818,350 | 5,121 … 123,905 | 导入成功并写入目录 |
| 7 / 8 / 12 / 16 MiB | 7,357,379 … 16,790,834 | 138,753 … 310,785 | `EXR_LIMIT (6)`，无目录行 |

上限落在 **123,905 与 138,753 个文本块之间**（131,072 = 2¹⁷ 是可能的内部分界，需 SDK
owner 确认，本包不据此下结论）。

处理与授予：TXT 子组按拒绝结论跳过，原因写入 `summary.skipped_cohorts`；
**「导入 16 MiB 单文档 TXT」保持未授予**；EPUB 导入作为独立样本保留；首屏、书架分页、
搜索、书内翻页、继续阅读、工作集与产物身份等范围照常声明（仍非性能达标）。

交回 root / G01 的最小复现与建议：

- 固定输入：按上文参数生成（首行 `Perf Import 0000`、每块 512 行、写满 16 MiB），
  16,792,975 字节 / `4f45393b…fc0a86`；7 MiB 变体同样复现。
- 明确状态：`导入失败：超出宿主或SDK限制（Native parser failed (6)）`，EXR 码 6；
  约 0.2 s 返回，无遗留 SDK 原件，产品目录不变。
- 建议：由 SDK owner 明确单文档 TXT 的文本块/行数上限并写入公共 API 文档；宿主已如实
  显示限额错误（未把失败伪装成成功）；产品可在导入前按上限提示。本包不改 SDK、不放宽
  等待、未把失败改记为预期拒绝。
