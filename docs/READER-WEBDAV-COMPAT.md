# WebDAV 客户端兼容性修复

起点 `210403d121d6484a8fff4ea7ffd911efa3163535`，SDK K 与产品 schema1 均不改。
此候选修复共享客户端，真实 Apache/Nextcloud 服务包继续独立验收。

1. 原 XML 全局 20000 元素上限会在 Apache 为不存在的 displayname 另发 404 propstat
   时，提前拒绝仍在 4 MiB／2000 项范围内的合法列表。现在最多接收 `max_entries+1`
   个 response（含集合自身），每个 response 最多 32 元素，response 外最多 128 元素。
   原深度 32、文本长度、命名长度、4 MiB 应答与 2000 条目上限保持，超限整份拒绝。
2. 缺少成功的 displayname 时，从已经验证的 URI component 解码一次 UTF-8 显示名。
   `resource` 继续使用编码后的路径；不拿显示名构造路径。
3. `%25` 表示普通百分号时允许，例如 `100%25.txt`。如果一次解码后的 segment
   还含 `%HH`，继续在网络前拒绝，保留现有第二重编码拒绝语义；分隔符、控制字符、
   非法 UTF-8 和路径越界的检查不变。

`reader-webdav.yml` 保留原 Linux 77／Windows 76 检查，另跑 12 项安装后消费者
回归：2000 项双 propstat、2001 项拒绝、降低限额、分项结构预算、外部元素、深度、
百分号与 Unicode 显示和真实请求路径。构建、测试与证据处理只在 Actions 执行。
首次候选尚待云端结果，不授予真实服务包、移动端或 UI 验收。

互操作包接续时，应先合入此共享修复的受测提交，再固定新的客户端源码起点。
包内 scope guard 继续要求 extras 与该固定客户端树相同，避免放开共享源码所有权。
既有两条“百分号明确拒绝”的场景改为验证上述精确兼容契约，并保留旧失败及原始报告。
