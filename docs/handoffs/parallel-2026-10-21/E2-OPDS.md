# E2：WP15 OPDS1/2 独立客户端子包

你负责可独立消费的OPDS客户端与固定云端验收。先读同目录`README.md`；直接实现协议、获取和消费链路，不等待其他宿主包，也不把只有feed解析器算成整个子包。

## 起点与产品范围

- 分支：`codex/wp15-opds`；实现基线`a2552d7feb786cd2345d2b0b3eb894777b3254db`。
- OPDS1 Atom与OPDS2 JSON分别冻结支持表：目录、出版物、作者/标题/标识、分页、搜索、获取关系、媒体类型与错误行为。
- 网络、凭据和下载位置由宿主控制；复用系统或标准库能力，交付独立模块和可运行消费示例，不向默认C SDK加网络运行时。
- 本包不做LCP，不实现支付/借阅服务，不要求真实账号。涉及受保护获取时明确返回需要相应宿主能力。

## 实现与接口

1. 定义稳定的feed/entry/link/search/result模型，保留未知关系和类型供宿主判断。Atom命名空间、XML base、相对链接、URL编码和OPDS2结构须有实际覆盖。
2. 导航与获取分开，分页结果可继续拉取；搜索支持声明的模板与参数，避免只对单个固定URL有效。
3. 网络适配明确请求、状态码、超时、取消、重定向与凭据来源。跨源跳转不自动转发原凭据；日志/报告不保存密码或令牌。
4. 明确feed字节、元素/条目、嵌套、跳转/分页和下载预算，超限返回受控结果；不改变SDK原预算。
5. 下载采用同目录临时文件与原子发布，处理已有文件、取消、源/目标别名及失败清理；保存完成后调用公开SDK或现有检查工具验证可消费书籍。
6. 同一原书重复获取和服务器声明类型与内容不符要有确定行为；不能因下载成功就宣称阅读成功。

## 文件所有权

独占`extras/opds/**`、`tests/opds/**`、`tools/check_opds.py`、`.github/workflows/wp15-opds.yml`、`docs/WP15-OPDS.md`、`docs/validation/wp15-opds*.json`。

公开消费参考`include/exr/formats.h`、`document.h`、`library.h`及`tools/check_document.c`。既有转换工具的发布保护只作参考，不修改`tools/convert*.c`或私有接口。各宿主接入本模块留给后续联合包，不能修改E3/E4/E5的目录。

## 云端量化出口

- OPDS1与OPDS2各至少10个具名场景；必须同时覆盖导航、分页、搜索、获取、认证响应和坏数据，不能只用20份静态feed凑数。
- 云端启动固定本地HTTP测试服务，真实请求并验证链接解析、分页/搜索参数、重定向、超时与取消。测试服务只在GitHub runner运行。
- 至少一条完整目录→搜索/翻页→选择出版物→下载EPUB→公开SDK打开/读取元数据链路；PDF或其他类型按声明能力另测。
- 覆盖下载目标已有文件、取消/失败不发布、无剩余临时文件、预算拒绝及重复获取。保留每案请求类别/输入散列/结果，凭据值不入报告。
- 独立消费示例在Linux与Windows云端运行；证明未修改默认SDK依赖/ABI/schema。
- 每个声明支持项均有正例和明确拒绝结果；未知或未执行不能计通过。
