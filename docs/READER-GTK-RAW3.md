# Explicit GTK raw3 host candidate

Status: **candidate; complete same-source acceptance pending**.

This branch ordinarily merges sealed GTK compact `9fc407a5`, accepted raw
families/metadata `0889f7d1`, and the shared private capture codec `4ad6f956`.
The production pin is `4b189aca819d9c5d1a7e73a6c5bbe0b2e8286f6e`.
SDK source remains `edddc463c06ed5731195cdb8f06b2df6dff7699e`; SDK3.41,
schema1 and the old MAX2/public wire contracts remain unchanged.

`EXR_READER_GTK_RAW3` defaults OFF. ON requires Linux, SDK3.41 and one explicit
installed provider prefix. Revisions use 0.4; commands, metadata, reading-state,
reading-commands, annotation-view, sync and session use 0.2. Each target's
actual header/archive origin is checked. The reading-state codec carries raw
capability; its SDK resolver is separately checked against the same provider.

The real worker dispatches received history, metadata/bootstrap, record views,
selected heads, raw capture resolution and reading commands through explicit
raw APIs. The account UI creates the raw native session. Fixed anchor3 uses
the public fixed-v3 resolver; retained v1/v2 keep their original resolver.
NULL exact selectors remain unresolved, with jump/text editing refused.

New private pending version2 stores the shared native capture as canonical
Base64, plus explicit writer/source versions and mode. It keeps SDK point,
range, route, length and NULL tags until the actual public command commits.
New fixed captures write3; reflow/EPUB write2; restores retain historical1/2/3;
text edits retain their selected source version. Delete stores mode only.
Old GTK pending version1 retains its exact key shape and original wire and
always retries writer2. No pending migration or public wire encoder is added.

The new workflow preserves all 35 original actual producer steps, including
compact45 and the complete original OFF suites, fixtures, judges and budgets.

and session-only sync, received/import/resolve/reopen, then all original
compact45 cases again on the raw program. Only a full seven-job same-source
run and strict ZIP authentication can accept this combined scope.
