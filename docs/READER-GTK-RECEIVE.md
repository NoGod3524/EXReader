# GTK 显式接收与原生阅读接续

起点为 `d2b59e9e9b3ad3e3246c23926f0fbebbaa9515f8`。SDK 固定
`9854061be331fe603a1822d9b2b36ee357154927`，产品 schema1 与同步 wire 保持。

Sync 只保留已验账号扫描、原书缓存和历史。用户选择 Receive books 后，既有 SDK owner
每批最多50行、逐书投影 SAFE 唯一头；缺父项、多头和删除恢复状态不猜选。
冲突书籍显示独立的有界版本列表。打开云端书行属于显式接收动作；缺缓存时先通过
实际账号会话下载，等待 CLOSED 后再导入，SDK 句柄不进入网络线程。

缓存经 no-follow 打开、长度与 SHA-256 检查后，用64KiB缓冲复制到私有稳定文件。
侧载导入及本机映射保留云端 title/author/favorite；SDK 已提交而映射失败时保留原书，
Retry 通过精确去重修复。导入前释放当前借用源，完成后先重开原有阅读位置，再处理用户
明确请求的新书切换。导入取消、失败不以远端位置替换当前页面。

接收端通过已安装 reading-state 包检查选中进度与标注，使用独立公开 SDK 文档、
EPUB spine 身份和固定页 ID resolve，不创建 SDK 笔记副本，不写当前阅读进度。
每次打开最多检查100个标注，并明确报告还有后续项；全局重排兼容投影限制32MiB，
大 EPUB 的旧全局记录保留为未解析。完整产品标注编辑与分页视图由后续宿主接线交付。

云端工作流 `reader-receive-linux.yml` 保留 GTK 原105项、4项故障、账号原23项、
安装后消费者及有界书架后端，追加22项：实际四格式收取、SAFE投影、缺缓存下载、损坏/链接拒绝、
SDK提交后映射失败与同ID去重重试、原有阅读恢复和公开 v2 resolve。账号与接收合计45项。
构建、语法、夹具、测试及证据解析只在 Actions。

前三轮分别保留安装包搜索路径、SQLite提供者身份和接收测试helper作用域失败；
最新源码待完整云端复验，不授予通过。真机、读屏、性能预算和六目标互通仍分别验收。
