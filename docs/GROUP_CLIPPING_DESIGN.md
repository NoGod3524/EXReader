# 组区域裁小与内存（工作包 3）设计

状态：**设计阶段**。当前组一律按整画布预留工作像素。

## 现状与成本

`exr_canvas_begin_group` 按画布尺寸分配：RGBA8 位图 4 B/px + 非隔离组的 5 个 float（20 B/px），
合计 24 B/px；单组上限 64 MiB，即约 2.8 M 像素。1000×1500 的单组固定预留 36 MB，
与组实际画了多大无关。

## 目标（工作包 3 验收）

- 小组（面积 ≤ 画布 10%）的工作像素预留较整画布**减少 ≥80%**；
- 既有探针像素完全一致；
- 1000 次创建/提交/丢弃无泄漏；
- 同机交替 ≥5 轮，六场景首画/重画 p95 回退 >10% 必须调查；
- 保留单独的高分辨率成功/超限测试。

## 方案

组的工作缓冲改按**绘制区域**分配，而不是整画布：

1. 进入组时已知继承裁剪（`c->clip`）。取裁剪掩码的非零包围盒作为初始区域；无裁剪时先用
   整画布，等第一次绘制后按实际落点收缩（或延迟分配）。
2. 位图与 `pixels` 状态都带 `left/top` 原点；`read_rgba`/`write_rgba`、纹理路径、复合路径
   的索引改为 `(y-top)*width + (x-left)`，越界即视为透明（与裁剪外一致）。
3. 提交时仍走 `exr_composite_frame`，用区域原点把局部坐标映射回画布。
4. 计费按实际分配字节，不再按画布面积；64 MiB 单组上限保持不变。

## 风险

- 所有像素路径都假定「位图尺寸 == 画布尺寸」，改动面涉及 `blend.c`、`vector.c`、`canvas.c`、
  `raster.c` 与图像纹理路径；必须用现有 50 个挖空场景 + 41 个软遮罩场景 + 全部 PDF 夹具回归；
- 区域的伸缩会让同一场景的中间缓冲尺寸变化，性能采样需要同机交替对照。

## 步骤

1. 先测量：记录六个常规场景的当前 24 B/px 预留与峰值，作为对照基线；
2. 只对**非隔离组的状态缓冲**做区域化（改动最小），验证像素一致；
3. 再把 RGBA8 位图也区域化，达到 ≥80% 的验收线；
4. 泄漏与交替性能测量；
5. `pager.c:advance` 拆分与测试脚手架收敛放在本包末尾做，避免与区域化改动互相干扰。
