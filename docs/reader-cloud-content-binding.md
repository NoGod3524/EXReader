# 云端导入下载内容绑定候选

基于 composition `11042994df180754a11e6d5f828df4277e839c3d`。面向用户自己控制的 HTTPS 云盘/WebDAV：新增下载观察入口，旧 WebDAV 0.2.0 包版本、旧函数、旧结果结构和调用语义保留。观察器在临时文件写入成功后按顺序看到正文，失败或取消时调用者丢弃状态；redirect 正文不交付观察器。内容绑定候选每次名字冲突重试重置 SHA-256，提交后仍执行原有路径读回，只有读回长度及摘要与本次网络写入一致才交出 staged；导入时维持现有再次校验与已打开对象读取。

原 `EXReaderCloudImport` 0.1.0 默认保持原依赖和行为，可继续搭配旧 WebDAV 0.2.0。显式开启 `READER_CLOUD_BUILD_CONTENT_BOUND` 才额外生成独立的 `EXReaderCloudImportContentBound` 0.1.0，依赖同一安装中的 `EXReaderWebDAVObserved` 0.1.0 能力包；旧 WebDAV 库没有该能力包或新符号。宿主改为查找和链接新候选目标才能采用内容绑定；两个目标提供同名 C API，CMake 会拒绝同一目标同时链接它们。未改动 Windows 或其他现有宿主的选包。

这是内容绑定，不证明发布路径和下载临时文件是同一个文件对象。清理仍按路径，依赖宿主控制的稳定私有暂存目录；POSIX 另一写入句柄可在校验和导入之间修改已打开对象。Windows 的初始发布仍关闭临时句柄后按路径移动。没有原子比较删除保证，也没有跨平台对象身份保证。PDF 描述符路径、Windows 父目录持有和移动平台限制仍按先前候选的实际范围。

仅 Actions 分别对旧 WebDAV 和旧云导入的组合、以及新候选使用原 HTTPS 九格式、取消、错误、静态损坏、独立 SDK 原件读回等普通检查，增加已安装 WebDAV 观察回调的正常正文、同源重定向、名字冲突重试和取消检查，确认 CMake 拒绝混链。普通回归不证明并发竞态安全；D13 保持未验收，不执行原被阻断实验、路径替换、攻击或 canary。无本地构建、测试、语法或工件解析。
