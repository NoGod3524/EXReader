# ExReader audit — 2026-10-22

Baseline: `9dfb155a1e42a5ee82fabc4beea41db575a309fa`, engine 3.39.0, Windows GCC Release.

**15 confirmed findings: 3 P1 and 12 P2.** Eight findings are new in this audit; seven remain open from the October 20 audit. The highest priorities are batch conversion overwriting source files, CBZ error cleanup crashing the host, and ignored per-item overwrite protection.

This audit reviewed conversion I/O and manifests, media decoding/CBZ, PDF read/edit paths, SVG font rendering, and Swift/JNI ownership and native host navigation. The existing regression suite covered the broader engine. No engine, tool, binding, host source, or original fixture was modified. This report and evidence are new files.

## Priority findings

### A01 — P1 — A batch output can overwrite another item's input [new]

Location: `tools/convert.c:622–628`, `642–661`, `1010–1023`.

Preflight checks each output against its own input and other outputs, but never against the other batch inputs. With overwrite enabled, a batch `a.txt → b.txt`, then `b.txt → c.txt`, replaces the original `b.txt` before its conversion starts. Both items return `ok` and the process exits 0; the second item converts A's content instead of B's original content.

Fix: compare every proposed output against the complete input set before publishing any item, including normalized paths and file identity. Reject output/input collisions.

Evidence: `build/audit-20261022/conversion/other-input/`, indexed in `conversion/summary.json`; original B's hash changed and both jobs succeeded.

### A02 — P1 — CBZ failure cleanup dereferences an unallocated page array [existing F1]

Location: `src/cbz.c:195–197`.

`page_count` can be nonzero when image probing or the frame-limit check fails before `*out` is allocated; allocation failure has the same problem. Cleanup unconditionally indexes `(*out)[i]`. An operation that should return `EXR_LIMIT` or `EXR_MEMORY` instead terminates the host.

Fix: only clean allocated and initialized records. Cover early rejection and allocation failure with recoverable-error checks.

Evidence: current-source control-flow verification plus the existing independent C/Python reproduction in `build/audit-completed-20261020/cbz-native-result.json` and `cbz-limit-result.json`. The current build did not require recompiling the unchanged engine DLL. This crash case was not rerun during this audit.

### A03 — P1 — Batch defaults override an explicit `overwrite:false` [new]

Location: `tools/convert.c:1282–1284`, `527`.

The manifest's top-level overwrite setting is folded into the CLI override before jobs are built. Consequently, top-level `overwrite:true` plus item-level `overwrite:false` still enables replacement through `cli_overwrite || spec->overwrite`. A disposable existing output was overwritten, and the item and process both reported success.

Fix: keep CLI authorization separate from manifest defaults; apply the manifest default only to items without an explicit overwrite value.

Evidence: `build/audit-20261022/conversion/item-refuses-overwrite/`; original output bytes changed despite the item's explicit false setting.

## Additional conversion finding

### A04 — P2 — NUL characters silently truncate manifest paths [new]

Location: `tools/convert_json.c:145–157`; consumed at `tools/convert.c:403–405`.

The JSON parser accepts `\u0000` into a C string. Subsequent string copies and path APIs use only the prefix. An output of `existing.txt\u0000-suffix` successfully overwrote `existing.txt` when overwrite was enabled. The actual destination differs from the manifest's string value.

Fix: reject embedded NUL in path strings and other fields represented as NUL-terminated strings, before preflight or file operations.

Evidence: `build/audit-20261022/conversion/nul-path/`; process exit 0 and the prefix-named file changed.

## Media findings

### A05 — P2 — CBZ source adapter rejects permitted short reads [existing F4]

Location: `src/cbz.c:58–63`; contract: `include/exr/base.h:72`.

The source adapter calls `read_at` once and treats a short result as an I/O error. The public source contract permits short reads and requires retrying. The same ordinary CBZ imports successfully with full reads but returns `EXR_IO` when the callback returns at most seven bytes, although all bytes remain available.

Fix: retry the remaining range, preserving cancellation, early EOF, and invalid over-return handling.

Fresh evidence: `build/audit-20261022/media/cbz-short-read.json`.

### A06 — P2 — TIFF alpha is multiplied twice [existing F2]

Location: `src/image_formats.c:279–284`; consumer: `src/affine_image.c:21`.

The TIFF decoder exposes associated-alpha RGB values as the common straight-alpha bitmap output. Composition applies alpha again, darkening translucent pixels. Existing equivalent PNG/TIFF fixtures differ after EXReader decoding; PNG agrees with the independent TIFF decoder. White-background composition differs by up to 54 channel levels.

Fix: normalize TIFF pixels to the public bitmap's alpha convention and verify translucent RGB, not only alpha endpoints.

Fresh evidence: `build/audit-20261022/media/tiff-alpha.json` and the two `alpha-*-white.png` comparisons.

### A07 — P2 — CBZ natural-sort ties interleave frames from different files [existing F3]

Location: `src/cbz.c:48–49`.

When natural comparison ties, frame number is compared before the full member name. Two existing animation fixtures named `page1.gif` and `page01.gif` therefore alternate frame-by-frame instead of placing all frames of one member before the next member. This violates the member-then-frame order documented in `docs/WP12A-FORMATS.md`.

Fix: settle member-name ties before comparing frame indices.

Fresh evidence: `build/audit-20261022/media/cbz-page-order.json`, including actual and expected page IDs.

## SVG font findings

### A08 — P2 — Stroke margins repeatedly enlarge the entire glyph bounds [new]

Location: `src/font_svg.c:1248–1249`.

Each shape is added to the shared bounding box, then its stroke margin enlarges that whole box, including previously measured shapes. One stroked rectangle renders successfully. One hundred identical overlapping rectangles have the same 40×40-pixel visible extent but produce a 4020×4020 allocation request and fail with `EXR_LIMIT`. These inputs are well below the declared node/path limits.

Fix: measure and expand each shape locally, then union that result into the glyph bounds.

Fresh evidence: `build/audit-20261022/pdf/svg-probes.json`, `bounds-accumulation`.

### A09 — P2 — SVG bitmap bounds clip supported miter joins [new]

Location: `src/font_svg.c:1245–1246`.

The fixed stroke-width margin ignores miter extension. A supported acute stroked path with `stroke-miterlimit="20"` loses 81 tip pixels. Adding an invisible rectangle, which changes only measured bounds, restores those pixels. The declared SVG subset supports miter joins and does not clip to the root viewport.

Fix: account for join/cap extents when measuring the surface.

Fresh evidence: `build/audit-20261022/pdf/svg-probes.json`, `miter-bounds`; paired `miter-natural.png` and `miter-padded.png`.

### A10 — P2 — Default SVG stroke draws a black outline [existing F5]

Location: `src/font_svg.c:1101–1112`.

Default state initializes opaque stroke and width without setting `stroke_none`. Omitting stroke and explicitly declaring `stroke="none"` should be equivalent; the ordinary comparison differs at 12,800 pixels.

Fix: initialize the default stroke to none and retain explicit/inherited stroke behavior.

Fresh evidence: `build/audit-20261022/pdf/svg-probes.json`, `default-stroke`.

### A11 — P2 — Percentage SVG opacity is rejected before unit parsing [existing F6]

Location: `src/font_svg.c:1124–1133`.

The first pure-number parse rejects a trailing percent sign before execution reaches the percent-handling branch. Supported `fill-opacity="50%"` fails while `fill-opacity="0.5"` renders.

Fix: identify/remove the unit before numeric parsing and compare equivalent decimal and percentage output.

Fresh evidence: `build/audit-20261022/pdf/svg-probes.json`, `percent-opacity`.

### A12 — P2 — Root SVG opacity is skipped [existing F7]

Location: `src/font_svg.c:1392–1398`, `1425–1429`.

Root attributes are applied separately and traversal starts at its children, bypassing the node-walk handling of overall opacity. Root `opacity="0.5"` differs from an equivalent single wrapper group at 25,600 pixels.

Fix: apply root compositing opacity with the same isolated-layer semantics as a group, including selected-glyph traversal.

Fresh evidence: `build/audit-20261022/pdf/svg-probes.json`, `root-opacity`.

## Apple reference reader findings

The following host control flows were reviewed statically. Their EPUB part listings, page counts, and deferred-load errors were reproduced through the current C API on Windows; the Swift UI was not run.

### A13 — P2 — Previous-chapter navigation depends on missing or stale page counts [new]

Location: `examples/apple/ReaderApp.swift:175`; related `99`, `181–190`.

`lastPages[part] ?? 0` sends Previous to the first page of the prior chapter after reopening, because `open()` clears this cache. Font changes leave old counts cached. The test chapter has 10 pages at size 28 and 33 at size 48; a cached page 32 becomes invalid after shrinking.

Fix: determine the preceding chapter's final page under the current layout, and invalidate layout-dependent cached counts.

### A14 — P2 — Page turning includes EPUB auxiliary documents [new]

Location: `examples/apple/ReaderApp.swift:171–175`.

Next/Previous increments through every publication part without consulting `inReadingOrder`. Existing `structure.epub` exposes two reading parts followed by `notes` and `nav`, both marked false. Next after the last reading chapter displays those auxiliary documents as chapters.

Fix: select adjacent parts in reading order while preserving explicit navigation to auxiliary documents.

### A15 — P2 — Failed chapter transitions leave location and content inconsistent [new]

Location: `examples/apple/ReaderApp.swift:172–179`.

The host commits `part/page` before loading, creating the pager, and rendering the destination. If the second chapter fails to parse, the first chapter's document/pager and displayed frame remain while the location points to chapter 2. Subsequent save/annotation operations can use that incorrect location.

Fix: prepare the destination state and rendered frame before committing the transition, or restore the previous state on failure.

Fresh evidence for A13–A15: `build/audit-20261022/bindings/evidence.json` and runnable `probe.py`. The deferred-error EPUB opens successfully, loads chapter 1, and rejects chapter 2 with `EXR_FORMAT` and no document.
