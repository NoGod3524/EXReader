# 版本分配

当前源码、头文件、运行库和安装 SDK 统一使用 **0.18.0 开发版**。
0.12.1 及以前的编号保留。其后的内部实现步骤归并为六个功能里程碑：

| 新里程碑 | 原开发编号 | 功能范围 | 原步骤终点提交 |
| --- | --- | --- | --- |
| 0.13 | 0.13–0.18 | 阅读基础：书内字体、分页检查点、随机读取、取消与进度、目录、结构化 EPUB 导出 | `7364142` |
| 0.14 | 0.19–0.38 | 格式解析：FB2、DOCX、RTF、MOBI/KF8 的结构、资源与封面，以及定位绘制模型 | `12f12cf` |
| 0.15 | 0.39–0.71 | PDF 阅读基础：对象与解压、字体与绘制、固定页接口、文字搜索选择、书库页进度与备注 | `792076e` |
| 0.16 | 0.72–0.78 | 有声书与宿主接入：时间线、同步、播放控制、WAV、续播书签、Swift/JNI 基础 | `2aa97a9` |
| 0.17 | 0.79–0.90 | 文档与定位增强：RTF 表格及列表、HTML 资源导出、书库去重、EPUB CFI | `fb49403` |
| 0.18 | 0.91–0.100 | SDK、索引与标注基础：ABI 约定、安装包、全文索引、进度与标注迁移、标注交换、PDF 元数据及原生标注读取 | `6ed05b0` |

这些范围用于归类已完成的开发工作。当前框架仍处于开发阶段，各格式支持范围以
[接口文档](NATIVE_API.md) 和 [验证记录](NATIVE_VALIDATION.md) 为准。
0.18 开发中继续补入 PDF Text/Highlight 标注写回、删除和原生标注 Form 外观绘制，
沿用当前版本，通过提交记录追踪。写回仅支持文件头版本至少 1.4 的 PDF；删除没有该版本限制，
均保留原文件字节。能力与验证范围见上述文档。
随后补入 Underline/StrikeOut/Squiggly、Unicode 17 默认 UAX #14、原生 FLAC、开放 PCM 和六平台声音输出适配。
再补入可见软连字符、可选 MP3、Info/XMP 原文件元数据写回及 Swift/JNI PCM 接入。
随后补入统一页面竖排、PDF Type3、可选 AAC/M4A/M4B 和 EPUB 原书元数据/封面写回。
再补入横竖混排块的页级续排、可变字体轴与原生变化定位、WSOLA 保音高变速和 PDF 内联图片。
其余标注类型编辑、表单、Indic 塑形、ruby、章内增量解析及手机真机验证等仍待完成。

## 历史记录

旧提交中的 `EXR_VERSION`、安装包、性能采样和 CI 记录保留原编号，便于核对原始产物。
接口文档中的 S013–S100 对应原 0.13–0.100 开发步骤。例如 S076 是安装后 WAV
示例验证，归入 0.16；S100 是 PDF 原生标注读取，归入 0.18。

Git 提交历史和已有阅读器预览版保持可追溯；不向旧提交补打与其实际版本声明不符的新标签。
当前没有为这些原生框架里程碑创建发行标签。旧 UI 阅读器的 preview-0.1.0 / preview-0.1.1
发行名称和下载内容保持原有含义。

ABI epoch 仍为 1，书库 schema 仍为 6。版本重分配不迁移用户数据，也不改变 C 接口。
安装 SDK 的 CMake 依赖统一改为 `find_package(EXReader 0.18.0 EXACT CONFIG REQUIRED)`，
避免误选编号较大的旧开发包。详见 [SDK 兼容约定](SDK_COMPATIBILITY.md)。

## 后续规则

- 次版本：一批可供宿主使用的功能完成接口、文档和相关验证后，统一升一次版本。
- 补丁版本：同一里程碑的缺陷修复和兼容性修正。
- 内部解析步骤、辅助接口、示例和验证改进：沿用当前开发版本，通过提交记录追踪。
- 发行标签与发布说明：在对应里程碑验收后创建，列明能力范围和未完成项。
- ABI epoch、数据库 schema 和产品版本分别管理，不能用产品版本号代替兼容检查。

## 后续兼容目标与验收顺序

以 MuPDF、CREngine、Readium、foliate-js 的能力作为对标方向。下面是 EXReader 的实现和验收目标，尚未完成的条目不表示当前已兼容对应项目。继续使用 C11 核心、GPL-3.0-only；平台阅读视图和服务接入独立于无 UI 核心。每个可独立验收的步骤单独提交，沿用当前开发版本，完整里程碑验收后才分配新版本。

| 顺序 | 工作 | 验收要求 |
| --- | --- | --- |
| 当前一步 | PDF CMYK/YCCK JPEG | 基线/渐进式、Adobe/无标记、Decode、颜色键/图像软遮罩、ICCBased、XObject/内联图及公开页面绘制；明确保留 ColorTransform override 的限制 |
| 1 | 加密 PDF 读取与认证 | 标准安全处理器 R2–R6、用户/所有者/空密码、可重试认证状态；RC4/AES、Crypt filter、元数据及对象流正确解密；权限可查询；错误密码不泄露部分结果。证书安全处理器作为另一个明确步骤验收。密码和密钥不落库，密码学使用经过验证的可选 C 组件 |
| 2 | PDF 透明度与色彩 | 隔离/挖空透明组、图形状态软遮罩 Alpha/Luminosity、混合模式、预混合 Matte、组色彩空间、输出意图与渲染意图，逐项做像素参考对比；区别已有的图像 SMask 与图形状态软遮罩 |
| 3 | 电子书表格 | 先实现指定列宽与按内容测量的最小/最大宽度分配，再实现单元格垂直对齐与 border-collapse；合并格、跨页、竖排、命中与 checkpoint 恢复一致 |
| 4 | 浮动图片与文字绕排 | float/clear、左右浮动和多浮动避让；逐行可用宽度、跨页续排、检查点及链接/选文坐标一致。以明确的 CSS 支持矩阵和图文用例扩展布局能力 |
| 5 | 按语言字典自动断词 | 开放语言/词典提供接口，字典可选加载；字形测量、连字符、字素保护、双向/竖排和随机页恢复一致；词典许可单独标明 |
| 6 | 交互表单 | AcroForm 字段模型、继承属性、值与选项、编辑校验、widget 外观再生成及保存/重开；动作和脚本执行能力单独界定 |
| 7 | 用户显式选择的安全 redaction | 预览/应用分离；应用时重写输出并清除历史修订和不再引用的敏感对象，处理文字、图片、Form、标注/表单及关联元数据。通过重开、提取、对象/原始字节检查验证；现有增量删除接口不能充当安全擦除 |
| 8 | OCR 集成 | 可选识别后端及语言模型，页图到文字/字格坐标映射、置信度、取消与资源预算；接入搜索、选文和标注，原生文字页避免重复识别；OCR 不自动替代安全 redaction |
| 9 | 应用阅读接入 | 可嵌入平台阅读视图、最小示例 App、输入/选择/缩放/翻页；TTS 的稳定文本位置、进度高亮与系统语音适配；无障碍语义树、阅读顺序和 VoiceOver/TalkBack/桌面屏幕阅读器验证 |
| 10 | 书目与受保护出版物 | OPDS 1/2 分页、搜索、获取关系和认证接口；网络/凭据由宿主控制。LCP 通过独立可选适配层接官方实现和授权流程，明确平台、许可与分发条件 |
| 贯穿各步 | 兼容文档与轻量化 | 发布时附版本化 API 文档、迁移说明和示例；持续记录 DLL/SO 体积、打开时间、峰值内存与翻页延迟。OCR 模型、字典、TTS/网络及保护出版物组件按需接入 |
