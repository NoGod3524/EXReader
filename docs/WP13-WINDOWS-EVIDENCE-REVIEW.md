## 已修正的证据出口

- 原检查器只要求总步数至少20；现逐phase要求原120/29/9条，STEP索引、顺序与动作必须和原脚本一一对应。
  缺失、重复、未知行、失败记录、重复字段、不合法UTF-8、提前/重复/矛盾DONE均拒绝。
- 原截图仅遍历已记录SHOT；现按原脚本强制A/B/C各5/2/1张及确切名称。
  SHOT须对应当前snapshot动作，文件名不得逃逸，PNG签名/IHDR尺寸和宿主nonzero标记均须有效。
- HOST按实际制表符格式解析，逐phase校验phase、实际启动PID及运行时版本；不再记录为空对象。
- 原26检查报告必须有正确schema、passed、精确检查数及版本，并匹配构建清单登记的报告与PNG散列。
  构建清单必须包含程序、唯一运行库、字体/许可和全部原书；源SHA、SDK版本及完整文件表均须匹配。
- 执行前封存：消费程序、打包程序、安装SDK运行库/头文件、固定字体、原书、额外输入及其清单、
  原始/实际执行脚本、检查器与宿主源文件。程序与消费构建、运行库与安装SDK、字体与固定来源、
  原书与构建清单、额外输入与生成清单分别核对。
- 每次启动前检查封存身份，全部阶段结束后再核对封存、源码及封存文件本身；变化不授予通过。
  原始阶段日志、stdio、实际脚本和截图附散列。A/B/C非零退出仍拒绝，既有恢复/所有权/取消条件保留。

原宿主日志未逐项回显resize/drag/note等动作参数；这些参数绑定到封存且实际传给原宿主的脚本及STEP索引，
