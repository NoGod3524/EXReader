# 原生轻量阅读核心工作包

2026-10-22。当前执行路线；取代历史二十项队列作为下一核心版本的排期依据。
定位：保留多格式解析、自有 PDF 渲染和 C SDK，不依赖 WebView，优先正确性、轻量、低延迟与有界内存。
本文件登记任务划分；实际完成状态以下方“当前执行状态”及其引用的固定源码与 run 为准。

R1 的轻量配置通过组件选择实现。PDF 密码认证、必要图像/字体和显示正确性按声明场景保留，
新增裁剪必须明确支持边界，不能为了缩小体积静默退化已有标准配置。
R3 首轮用于确定预算，尚未测量的 MB/ms 数值留空；共享云 runner 的噪声和冷缓存不可控情况须登记，
不能把不同硬件的结果当作同一性能保证。
R2/R4 的解析和资源管理修复必须保留针对性畸形输入、取消、预算及 ASan/UBSan 回归；
R6 的核心门禁保留所有已声明格式的现有正确性回归。缩减功能排期不缩减已交付接口的质量要求。

## 并行与合入顺序

先并行准备 R1、R2 的清单/诊断、R3 测量工具和 R6 协议；共享构建文件由 R1 负责，门禁由 R6 负责。
冻结配置与初始语料后测基线，再按真实热点启动 R4。R2/R4 共享核心文件的改动逐项合入并验证。
R5 按平台独立分支推进，宿主采用哪个 SDK 必须登记固定源码；所有代码合入后按变化范围复验。
以一个平台建立首轮性能预算，其余平台完成正确性/构建验证并分别计量，避免一次启动全部平台优化。

所有构建、测试、语料生成、benchmark、模拟器和证据汇总在 GitHub Actions 执行；本地只做源码/文档和 Git 操作。
路线文档的更新本身不启动代理、测试或新的功能实现；R1/R3 的云端运行另见当前执行状态。

## 按需积压

安全 redaction、PubSec/EFOpen/加密写回、OCR 文字层、高保真转换、TTS、OPDS/LCP、
完整应用服务与新增罕见格式子特性按真实需求重新立项，不自动列入下一核心版本。
JPX/JBIG2、Pattern、复杂色彩/透明组合或 CSS 余项若被 R2 证明阻碍常用文档，应按影响提升为阅读缺陷任务。
已发布接口的正确性、安全清理和依赖许可继续维护。未来交付面向最终用户的宿主仍需相应无障碍与真机验收，
它们属于宿主出口，不能用核心 SDK 通过替代。

核心版本的完成依据是：声明范围内可靠阅读、预算满足、可安装接入、依赖/许可清晰和可追溯发布。
不再用历史二十项功能的完成比例衡量核心版本。
