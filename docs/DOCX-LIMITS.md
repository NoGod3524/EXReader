# DOCX Explicit Limitations and Conservative Preservation Boundaries (`DOCX-LIMITS`)

EXReader's editable DOCX bridge (`exr_edit_docx_read` / `exr_edit_docx_write`) and document/paragraph/table/image editing model (`exr_edit_*`) follow a strict **zero-silent-data-loss** policy. The goal of the bridge is lossless retention of source OPC package parts and non-targeted OOXML structures rather than re-implementing a full Word layout or field-recalculation engine.

Structures outside the active editable model subset are never silently stripped or flattened; instead, they are either **retained byte-for-byte** as opaque XML spans (`EXR_EDIT_OPAQUE_RUN` / `EXR_EDIT_OPAQUE_BLOCK`) + untouched OPC package parts, or **explicitly rejected with `EXR_UNSUPPORTED`** when an API call attempts to mutate them in place. Full round-trip and edit matrices across both 30-fixture suites (`argon` and `codex`, 60 fixtures total) are reported in [DOCX-REAL-RESULTS.md](DOCX-REAL-RESULTS.md).

## `exr_edit_set_run_text` & Verification Guarantees

1. **Single-Run Text Replacement (`exr_edit_set_run_text`)**: Replaces the UTF-8 text of one `EXR_EDIT_TEXT` run while preserving block and run IDs, direct formatting (`exr_edit_run_props`), original XML run/text templates (`opaque_xml`), and neighboring `EXR_EDIT_OPAQUE_RUN` siblings. Participates in transactions, `exr_edit_undo`, and `exr_edit_redo`. Invalid UTF-8, XML-forbidden control characters, out-of-range indices, and `EXR_EDIT_OPAQUE_RUN` targets are rejected (`EXR_ARGUMENT` / `EXR_UNSUPPORTED`) without mutating the document.
2. **No Silent Drop**: Unrecognized or unsupported elements in `word/document.xml` (including comments and processing instructions before `<w:pPr>` and after body-level `<w:sectPr>`) are captured by exact Expat byte-span slicing (`source_xml`) and emitted in their original lexical position on `exr_edit_docx_write`.
3. **Non-Target Part Preservation**: OPC parts outside the edited target are written back byte-for-byte. Header/footer text commands patch their referenced header/footer part while retaining its fields, paragraph properties and opaque XML. New header/footer/image parts update relationships and content types; header/footer flags update the selected section's `titlePg` and `settings/evenAndOddHeaders`.
4. **Transactional Atomicity**: Any command returning `EXR_UNSUPPORTED`, `EXR_ARGUMENT`, or `EXR_MEMORY` latches failure on the active `exr_edit_tx` transaction so `exr_edit_commit` automatically rolls back all prior changes in the batch with zero memory leaks.
