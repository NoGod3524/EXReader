# 阅读状态 v2：root 实施决定

决定采用 `READER-READING-STATE.md` 的版本化方向，补齐进度、点书签、无文字固定页、
完整文档的章节作用域和重复 spine 路径。此文固定实施契约，尚未授予 v2 验收。
SDK K、公开 ABI 和产品 schema1 保持；产品修订与适配模块独立升级。

## wire 契约

外层 `version:1` 与不可变修订、parents、全局 book_key、annotation_id 保持。
`location.anchor_version:2` 使用独立分支验证；anchor_version1 的字段及语义保持。

- `exact` 可为空，当且仅当 `start==end`。所有 v2 选择器均要求
  `end-start == exact` 的 UTF-8 字节数。进度必须是点；标注的点表示书签，非空范围表示高亮。
- `prefix/suffix` 各最多32标量、128字节，与冻结 SDK 的实际捕获相同。
  NUL、非法 UTF-8、越界整数、未知字段继续拒绝。
- `reflow_global` 的 selector 必填 `chapter`，值为原样非空路径或 null，保留真实作用域。
- `epub_chapter` 的 location 必填 `part` 与 `part_path`，接收端须同时匹配 spine 序号
  和路径，再进行公开 resolve。v1 继续只接受唯一路径路由。
- `fixed_page` 的 page_id 是路由身份，page 是受检提示。无文字页可用全空引文和
  `(0,0)` 点，仍须公开 resolve 为 FOUND。

旧 v1 字节不重写、不就地升级；v1 空引文等原反例继续拒绝。旧客户端对 v2 整份拒收，
不写入、不 ack，不把页号或偏移当作降级定位。旧端可因未知字段或未知 anchor_version
返回 FORMAT；具体错误文案取决于先触发的验证条件，不能只凭文案宣称兼容。

## 产品层持久化与全局身份

同步书签与标注以产品修订为事实来源，沿用全局 `book_key:annotation_id`。
SDK 负责原件、解析、布局与公开锚点解析；同步接收不创建或更新 SDK 本机笔记副本。
这样，进程重启后仍按同一全局 ID 查询、修改或删除，不需要用范围加文字认领本机 ID，
也不需要在两个数据库之间模拟原子笔记提交。

宿主列表、阅读页高亮和书签导航须消费产品记录。并发、缺父、删除后未显式恢复等状态
保留原历史并显示为待处理；只有 SAFE 且公开 resolve 得到 FOUND 才显示可定位结果。
未找到、歧义与旧式记录保留，不产生误定位写入。远端记录不改变当前正在阅读的位置。

既有 SDK 本机笔记仍保留。后续迁移是显式公开捕获→固定全局 ID→产品修订提交；
不删除旧笔记、不按近似文字静默匹配。现有 `reader_rs_store_*_note` 维持原有显式 API
范围，产品同步接入不调用它们生成远端副本。有界 EPUB 的点书签直接由产品记录承载。

## 必须跑通的出口

1. 现有 v1 协议59项、投影32项、类型命令33项及阅读探针121项逐项保留；新增 v2
   正反例、旧验证器真实拒收及 v1 字节不变。旧“未知版本”用例需使用仍未支持的版本，
   并另保留旧验证器对版本2的真实拒收证明。
2. TXT文首/多字节/文末点，EPUB章节进度、章首书签、重复spine，完整文档chapter，
   PDF/CBZ无文字页，经产品修订实际传输，在第二独立 SDK 库解析；零误定位。
3. 创建、编辑、并发、删除、显式恢复、乱序补父、重投、真实 kill/重开都按同一全局 ID
   保持唯一可见记录；不产生 SDK 笔记副本，不自动跳转活动阅读位置。
4. 真实 WebDAV 两端回路与四套原生壳分阶段接入；每个平台按实际证据授予。

当前已合入兼容性研究及两端探针交付，正在实施 v2；以上出口均不能以可行性研究替代。
